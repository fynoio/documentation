The **Central Dashboard** extends the Analytics Dashboard beyond a single workspace. Instead of opening each workspace one at a time to check how it is performing, you get one page that aggregates notification performance across all the workspaces you own.

Every metric, chart, and control works exactly as it does on the workspace Dashboard. What changes is the scope: data is rolled up across workspaces, and a workspace filter lets you narrow the view to any subset of them.

Use the Central Dashboard to:

- Monitor notification volumes across all your workspaces in one place.
- Compare delivery performance between workspaces.
- Spot a workspace that is driving unusual traffic or failing deliveries.
- Review channel and provider performance without switching workspaces.
- Investigate event-level delivery issues with workspace attribution.

<Note>
All metrics displayed throughout the Central Dashboard are affected by the selected **Workspace**, **Environment**, **Analytics Label**, and **Time Frame** filters.
</Note>

## Availability

The Central Dashboard is available to **Owners** and **Super Admins**. Workspaces are grouped based on their owner, and each group contains workspaces owned by the same user.

For Owners, the Central Dashboard shows only groups where you are the owner of all workspaces in the group. Workspaces where you hold another role, such as Workspace Admin, aren't included.

The **View Analytics** entry point appears only for eligible workspace groups and opens the Central Dashboard.

### Accessing the Central Dashboard

1. Open the **Workspaces** page. Workspaces with the same owner are grouped together under the brand name. The owner can edit the brand name as needed.
2. Select **View Analytics** to the right of the group heading to open the Central Dashboard for all workspaces in that group.
![](/images/central-dashborad-view-analytics.png)
<Note>
All workspaces in the group have the same owner. Owners and Super Admins can access the **View Analytics** option.
</Note>

## Global Controls

The controls at the top of the Central Dashboard determine the scope of data displayed across all widgets.
![](/images/central-dashboard-view.png)
### Top Bar Controls

| Control | Description |
|----------|-------------|
| **Workspace Filter** | Restricts the dashboard to one or more of the workspaces you own. |
| **Environment Toggle** | Switch between Live and Test environments. |
| **Analytics Label Filter** | Filter analytics using the labels configured for your workspaces to focus on specific data. |
| **Time Frame Filter** | Restricts data to a selected reporting period. Supported periods include Today, Yesterday, Last 60 Minutes, Last 7 Days, Last 28 Days, and Custom Date Range. The exact dates covered by the selection are displayed below the filter. |
| **Data Freshness Indicator** | Displays when the dashboard data was last synchronized, with an option to refresh. |
| **Status Guide** | Opens the reference explaining each delivery status. |

<Tip title="Quick Tip" color="green">
Use shorter date ranges while troubleshooting and longer periods when analyzing trends across workspaces.
</Tip>

### Workspace Filter

The Workspace Filter is unique to the Central Dashboard. It is a multi-select control listing every workspace you own within the group.
![](/images/workspace-filter.png)
Clearing the selection returns the dashboard to **All**.

<Tip title="Quick Tip" color="green">
Start with **All** to spot an outlier, then select that single workspace to investigate it without leaving the page.
</Tip>

## Key Performance Indicators (KPIs)

The KPI cards provide a high-level summary of notification volumes across the workspaces in scope.

| Metric | Definition |
|----------|------------|
| **Notification Events Fired** | Total number of notification event APIs successfully received by Fyno for processing during the selected time period. |
| **Notifications Requested** | Total number of notification requests received by Fyno for processing. A single event may generate multiple requests when several recipients or channels are configured. |
| **Notifications Sent** | Notifications successfully processed by Fyno and accepted by the provider for delivery. |

```text
Sent = Requested − (Error + Failed + Dropped + Timeout)
```

<Note>
On the Central Dashboard, each KPI is the sum across the workspaces currently in scope.
</Note>

## Channel Usage

The Central Dashboard provides channel-specific usage cards for **SMS**, **WhatsApp**, **Email**, and **RCS**. Use these cards to monitor usage, reconcile channel costs, and identify changes in consumption across the workspaces in scope. Select the expand icon on a card to view more detailed usage information.

### SMS Credits

The SMS Credits card tracks SMS credit utilization across the workspaces in scope, split between delivered and sent but not delivered volume. Select the expand icon to view more detailed credit usage, including usage by integration and destination country.

Use this card to:

- Reconcile SMS credit usage and costs across workspaces.
- Review credit usage by integration and destination country.
- Monitor SMS usage trends and identify unexpected increases in consumption.
- Estimate future credit requirements.

### WhatsApp Credits

The WhatsApp Credits card tracks WhatsApp credit utilization across the workspaces in scope. The expanded view provides more detailed usage information for deeper analysis and cost reconciliation.

Use this card to:

- Reconcile WhatsApp credit usage and costs across workspaces, broken down by message category (e.g., Marketing, Authentication, Utility, Service).
- Monitor WhatsApp usage trends.
- Identify unexpected changes in credit consumption.

### Email Credits

The Email Credits card tracks email credit utilization across the workspaces in scope. The expanded view provides more detailed usage information for deeper analysis and cost reconciliation.

Use this card to:

- Reconcile email credit usage and costs across workspaces.
- Monitor email usage trends.
- Identify unexpected changes in credit consumption.

### Filters

The detailed (expanded) views for the SMS, WhatsApp, and Email Cost Analytics cards support additional filters, giving you more granular control over the cost data you're analyzing.

| Filter | Description |
|--------|-------------|
| **Providers** | Narrow the cost breakdown to one or more specific providers. |
| **Integrations** | Narrow the cost breakdown to one or more specific integrations. |
| **Analytics Labels** | Narrow the cost breakdown to notifications tagged with specific analytics labels. |
| **Groups** | Narrow the cost breakdown to specific groups. |

Applying a filter updates the displayed cost analytics counts immediately, and only shows values relevant to the data available to you.

<Note>
These filters apply to the SMS, WhatsApp, and Email Cost Analytics details views only, and don't affect other analytics views on the Central Dashboard.
</Note>

## Channel Engagement

The Channel Engagement chart shows notification activity across each communication channel and the outcomes associated with those notifications, aggregated across the workspaces in scope.
![](/images/channel-engagement.png)
The available engagement metrics include **Attempted**, **Delivered**, **Read/Open**, and **Clicked**.

| Metric | Description |
|--------|-------------|
| **Attempted** | Notification requests that passed Fyno validation and were handed off to the provider. Attempted = Requested − (Error + Failed + Dropped). |
| **Delivered** | Notifications confirmed by the provider as having reached the intended destination. |
| **Read / Open** | Recipient viewed the notification. Read applies to WhatsApp and In-App, Open applies to Email. |
| **Clicked** | Recipient interacted with a link or actionable element in the notification. |

## Delivery Rates

The Delivery Rates table provides detailed delivery metrics for individual notification events. Using the grouping selector, you can view delivery performance by **Notification Events**, **Analytics Labels**, or **Workspaces**.

<Note>
On the Central Dashboard, each row also displays the workspace the notification event belongs to. Events that share a name across workspaces therefore remain distinguishable, and you can trace a low delivery rate back to the workspace it originated from.
</Note>
![](/images/centraldashboard-delivery-status.png)
Delivery rates that fall below the expected threshold are highlighted so that problem events stand out. Select **Expand View** to analyze channel-wise and provider-wise metrics for a selected row.

Use the Delivery Rates table to:

- Compare notification event performance across workspaces.
- Identify delivery bottlenecks at event level.
- Troubleshoot events experiencing high failure rates.
- Evaluate performance using Analytics Labels.

## Status Definitions

The **Notification Event Delivery Rates** table tracks notifications as they progress through different stages of the delivery lifecycle.

Understanding these statuses helps you identify where notifications are successfully progressing and where intervention may be required.

### Status Definitions

| Status | Description |
|---------|-------------|
| **Requested** | Total number of notification requests received by Fyno for the selected notification event. This represents the initial notification volume entering the processing pipeline. |
| **Error** | Notifications that could not be processed due to internal errors within Fyno. Examples include invalid configurations, missing templates, malformed payloads, or other processing exceptions. |
| **Failed** | Notifications rejected by the provider API and not accepted for delivery. Common causes include authentication failures, invalid request payloads, insufficient balance, provider unavailability, or other provider-specific validation errors. |
| **Dropped** | Notifications intentionally prevented from being sent because they did not meet processing criteria, such as suppression rules, frequency controls, user opt-out preferences, duplicate prevention, or workflow conditions. |
| **Attempted** | Notifications that successfully passed Fyno's validation and processing stages and were handed off to the configured provider for delivery. |
| **Timeout** | Notifications for which the provider did not respond within the configured timeout period. A timeout does not necessarily indicate delivery failure; it means Fyno did not receive a response within the expected time. |
| **Sent** | Notifications successfully processed by Fyno and accepted by the configured provider for delivery. |
| **Delivered** | Notifications successfully delivered to the intended recipient, based on delivery confirmations received from the provider. |
| **Undelivered** | Notifications accepted by the provider but not delivered to the recipient due to recipient, carrier, mailbox, or device-related issues. |
| **No DLR** | Notifications for which no Delivery Report (DLR) was received from the provider after the notification was sent. This is common for providers or channels that do not consistently support delivery confirmations. |

#### Percentage Calculations

When viewing the table in **Percentage (%)** mode, each status is calculated using the following denominator.

| Status | Percentage Based On |
|---------|---------------------|
| **Error %** | Requested |
| **Failed %** | Requested |
| **Dropped %** | Requested |
| **Timeout %** | Attempted |
| **Sent %** | Attempted |
| **Delivered %** | Attempted |
| **Undelivered %** | Attempted |
