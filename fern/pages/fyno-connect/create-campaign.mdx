Campaigns allow you to trigger bulk notifications to a select group of users that you have created via **Cohorts** through a specific **Notification Event** that you have pre-created in Fyno Cloud.

## Create a campaign

<Steps>
  <Step>
    Click on **Campaigns** from the left navigation bar. On the new page, click on **Create +** to create a new campaign. In the **Create Campaign** pop-up, fill in:
    <ul>
      <li>**Campaign**: Provide a suitable name for the campaign.</li>
      <li>
        **Campaign Type**: Select the type of campaign. This can be:
        <ul>
          <li>Engagement</li>
          <li>Onboarding</li>
          <li>OTP</li>
          <li>Promotional</li>
          <li>Retention</li>
          <li>Transactional</li>
        </ul>
      </li>
      <li>**Cohort**: Select the cohort you want to send to. If you selected **Save and Create Campaign** while saving a cohort, this is already filled in.</li>
      <li>**Workspace**: Select the workspace where you want to execute this campaign.</li>
    </ul>
    Click **Create**.
  </Step>
  <Step>The campaign page opens with a **Unsaved** label next to the name, and the selected workspace shown below it. Select a pre-created notification event from the **Notification Event** dropdown. The live version of the event appears next to the dropdown, and the open icon takes you to the event in Fyno Cloud.</Step>
  <Step>Fill in the **Configuration** section, described below.</Step>
  <Step>Click **Go To Testing**, send a test, and click **Test And Save**.</Step>
</Steps>

![](/images/connect_campaign_create_modal.png)

The campaign is created and triggered only after the notification event is called successfully.

## Configuration

![](/images/connect_campaign_configuration.png)

### Type

Select [One Time](#one-time-campaigns) or [Recurring](#recurring-campaigns).

### TO

Map each channel to the column in your cohort that holds that address. For example, if the notification event sends an email, pick the column that holds the email IDs. The channels you see here depend on the channels configured in the selected notification event.

### DATA

Map each placeholder in your template to the column in your cohort that holds its value. For example, if the template has a placeholder called `name`, select the column that holds the names. Click **Add Key** to add another placeholder.

![](/images/connect_campaign_configuration_filled.png)

The **Preview** panel on the right shows the template with your mapped columns in place, so you can check that every placeholder picks up the right column before you test.

![](/images/connect_campaign_preview.png)

### Include duplicate records in campaign

Duplicate records in the cohort are excluded by default, so a user who appears twice gets the notification once. Select this checkbox if you want to send to every record, duplicates included.

### Custom Parameters

Expand **Custom Parameters (optional)** to send extra values along with the notification. These values come back to you in the delivery report.

| Placeholders | Mandatory |
| ------------ | --------- |
| custom_id    | Yes       |
| custom1      | No        |
| custom2      | No        |
| custom3      | No        |

## Campaign Types

You can do 2 types of campaigns:

1. One-time - Enables you to run one-time campaigns.
2. Recurring - Enables you to setup a frequency at which you want your campaigns to run.

### One-time Campaigns

One-time campaigns allow you to execute a single campaign at a specific time. Ideal for announcements, updates, or special offers, these campaigns are designed to be delivered once without any recurring schedule.

### Recurring Campaigns

Frequency - Select the periodicity of the campaign. You can choose from one of these frequencies. 

| Frequency | Usage                                                                                                                                                                                  |
| :-------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Day       | You can select every hour or a particular time like 1 PM or more than 1 time slot like 1 PM, 4 PM etc.                                                                                 |
| Week      | You can select Every day of the week or a particular day like Monday or few days like Monday, Friday. You also need to select the time slot when you want the campaign to be executed. |
| Month     | You can select a particular day of the month and particular days in a month and also the time slots.                                                                                   |

When the campaign ends - Select after how many times you want the campaign to end.

## Test and fire the campaign

Click **Go To Testing** at the bottom of the configuration to open the **Testing** section. The fields here come from what you mapped in the configuration.

<Steps>
  <Step>Under **TO**, enter a real address for each channel, such as your own number under **SMS** or your own address under **Email**.</Step>
  <Step>Under **DATA**, enter a sample value for each placeholder. The **Preview** panel updates as you type, so you can see exactly how the message reads.</Step>
  <Step>Click **Test And Save**. Fyno sends the test to the addresses you entered and shows **Test successful for this configuration!** if the notification event was called successfully.</Step>
  <Step>Confirm the campaign in the **Confirm campaign fire** pop-up to send it to everyone in the cohort.</Step>
</Steps>

Click **Back To Configuration** at any point to change the mapping before you test again.

## Campaign run logs

Switch to the **Logs** tab on the right of the campaign page to see every run of the campaign, with the time it was processed and finished, the total number of records, and how many of them succeeded. Click the open icon on a run to go to that campaign in Fyno.

![](/images/connect_campaign_logs.png)

<Info title="Your logs are safe with us!">For every campaign triggered by you via Fyno Connect, the logs will be visible on **Notification Event logs** as well as the **Logs** page. Head on over to the **Logs** section and find insights about your campaign.</Info>

## Duplicate or delete a campaign

On the **Campaigns** page, click the ellipsis at the end of a campaign to:

- **Duplicate**: Create a copy of the campaign with the same configuration, which you can then edit and fire separately.
- **Delete**: Remove the campaign.

![](/images/connect_campaign_duplicate_delete.png)

## How to use Content APIs in Campaigns

Content API feature enables you to configure your API end points in Connect and use it to fetch any data and use it in your campaigns.

You can read more about it [here](https://fyno.io/docs/how-to-add-content-apis-in-fyno-connect#how-to-use-content-api-in-campaigns).

## How to receive delivery reports?

Fyno allows you to forward delivery reports to your own system or integrate them with third-party analytics tools like Mixpanel and Amplitude. This feature enables you to track and analyze the success of your notification deliveries seamlessly.

By sending delivery reports to your preferred systems or analytics platforms, you can gain valuable insights into the effectiveness of your notification strategies and make data-driven decisions to optimize your communication processes. Fyno's flexibility ensures a smooth integration with your chosen tools, empowering you to monitor and improve your notification performance.

- To configure callbacks to receive delivery reports, select the checkbox **Send data to my allowlisted endpoint(s)**.
- This option allows you to receive Delivery reports of each notification triggered in any URL you have allowlisted in Fyno.
- Select up to 3 endpoints from the **Allowlisted Endpoints** dropdown. If you have not allowlisted any URL yet, refer to this [doc](./configuring-allowlist-url-sqs-to-receive-delivery-report) and add a new URL.

  ![](/images/connect_delivery_report.png)

Once the endpoints are selected, you can send up to 3 additional placeholders back in the callback URL using [Custom Parameters](#custom-parameters).

## How to throttle a campaign?

Throttle is optional but we recommend using it. Throttling allows you to control the rate at which notifications are sent to users.

In the **Throttle (Optional)** section, click **Add**, then select **By Time** or **By Batch**. Click **Cancel** to remove the throttle.

![](/images/connect_campaign_throttle.png)

![](/images/connect_campaign_throttle_options.png)

### By Time

You can specify a duration for which the campaign should run. You can have a minimum of 15 minutes and a maximum of 180 minutes. For example, if you want to execute the campaign for an hour, you can do that by entering 60 minutes.

![](/images/connect_throttle_time.png)

### By Batch

In this option, you can throttle the number of records the campaign should send for a specific duration. You can have a batch size between 1,000 and 50,000 records, and a time limit between 1 and 60 minutes. For example, if you want to send a batch of 1,000 records every minute, enter 1000 records and 1 minute.

![](/images/connect_throttle_batch.png)
