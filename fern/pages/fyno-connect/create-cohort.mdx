To create a one-time or recurring campaign, you need to create a cohort as first step.

## What is a Cohort?

A Cohort is a collection or a segment of users created on a set of filters or a database query. This allows you to segment users based on any criteria and send targeted messages to them.

A few examples of filters include filtering by specific status, location, or sign-up timestamp. There are countless other possibilities that you can explore by using different combinations of filters or writing your own query.

## How to create a cohort?

Let's have a look at how to create a cohort.

<Steps>
  <Step>From the left navigation panel, click on **Cohorts**. The page lists every cohort in your account with its database, when it was created and updated, and who created it. Use the search box to find a cohort by name.</Step>
  <Step>Click **New Cohort**.</Step>
  <Step>In the **Create New Cohort** pop-up, enter a name for the cohort, pick a database from **Select Database**, and click **Submit**.</Step>
  <Step>The cohort page opens. The **Select Schema** dropdown lists all the schemas present in the selected database.</Step>
  <Step>Select a schema to view its data in a table below. Use the **Filter** tab or the **Query** tab to get the segment of users you want.</Step>
  <Step>Click **Save Cohort** to save the selected schema along with the applied filters or query and complete the cohort creation process.</Step>
  <Step>Alternatively, you can click the arrow next to **Save Cohort** and select **Save and Create Campaign** to not only save the cohort but also create a campaign from it.</Step>
</Steps>

## Filters and Query Builder

Filters and Query allow you to get the segment of users for certain conditions or factors. Switch between the two using the **Filter** and **Query** tabs.

### Filters Builder

A powerful visual builder using which you can apply a set of filters to the schema data to get the desired output. This builder consists of the following major components:

#### Rule

It is the most important component as it consists of the single condition or the filter that needs to be applied.

A rule is created by combining 3 things:

```
Rule = Key + Operator + Value
```

The "Key" is the column name or the object key from your schema. It is present as a dropdown menu with a list of column names or object keys from your schema.

The "Operator" is the operation or check that is to be performed between the key and the value. It is present as a dropdown menu with a pre-defined list of operators.

The "Value" is the data value that you input. The data type of this field will depend on the "Key" selected and will change as you change the selected "Key".

Example of a rule:

```
Age > 30, Company = Fyno, Email ends with @fyno.io, and many more.
```

Click **Add Rule** to add another rule to the same group.

![](/images/connect_cohort_key_dropdown.png)

#### Operators

These are the operators you can pick from:

| Operator | What it does |
| --- | --- |
| `=` | Matches rows where the value is exactly the same |
| `!=` | Matches rows where the value is different |
| `<`, `>`, `<=`, `>=` | Compares numbers and dates |
| `contains` | Matches rows where the value appears anywhere in the text |
| `begins with` | Matches rows where the text starts with the value |
| `ends with` | Matches rows where the text ends with the value |
| `is null` | Matches rows where the column has no value |
| `is not null` | Matches rows where the column has any value |
| `in` | Matches rows where the value is one of the values you list |
| `not in` | Matches rows where the value is none of the values you list |
| `between` | Matches rows where the value falls within a range, including the ends |
| `not between` | Matches rows where the value falls outside a range |
| `last X days (Range)` | Matches rows from the last X days up to today |
| `last X days (Exact)` | Matches rows from that one day, X days ago |

#### Get Distinct Rows

Use the highlighted icon to instantly see the unique values in your selected column, up to the first 1000. This automatic detection saves time, especially when working with large datasets, by showing you the possible filter values in a convenient dropdown menu.

![](/images/connect_filters_distinct.png)

#### Group

A group is a collection of rules that can be used to organize filters and create complex filters by combining multiple groups with different combinators. Click **Add Group** to add one.

#### Combinators

Determine how 2 rules or groups will combine together in order to form a complete condition or a filter. It can have 2 values:

1.  AND: The "AND" combinator evaluates to true if both of its rules or groups are true. If at least one of the it is false, the entire combined condition evaluates to false. The "AND" operator can be thought of as representing the intersection of conditions.
2.  OR: The "OR" operator evaluates to true if at least one of its rules or groups is true. If both are false, the entire combined condition evaluates to false. The "OR" operator can be thought of as representing the union of conditions.

Click the combinator between two groups to switch it between AND and OR.

![](/images/connect_cohort_groups_and.png)

<Tip>After completely adding all the rules and groups, hit the **Apply** button to filters and view the updated data below.</Tip>

### Query Builder

A simple code editor to write or paste your db queries and run it directly on the schema data to get the desired output. This editor gives you more freedom as you can write as complex a query as you can and also helps you reuse what you have already written someplace else.

It's essential to use the appropriate query when working with different databases. For instance, MongoDB requires a JSON-formatted Aggregation Pipeline query which looks like this:

```json
[
  {
    "$match": {}
  }
]
```

#### Generate a query with Fyno AI

Don't know how to write a database query? Describe the set of users you want in plain English, and Fyno AI converts it into a query that runs on your schema data.

For example, if your `user` table has `created_at` and `language` columns, you could type:

```
Get the User_id, Name and Email of users who signed up in 2026 and whose language is English.
```

Fyno AI generates the query in the right format for your database:

![](/images/dev-mysql-ai-query.png)

Here's the query for this prompt in each supported database:

<CodeGroup>
```json MongoDB
[
  {
    "$match": {
      "created_at": {
        "$gte": { "$date": "2026-01-01T00:00:00Z" },
        "$lt": { "$date": "2027-01-01T00:00:00Z" }
      },
      "language": "en"
    }
  },
  {
    "$project": {
      "_id": 0,
      "user_id": 1,
      "name": 1,
      "email": 1
    }
  }
]
```

```sql MsSQL
SELECT t1.[user_id], t1.[name], t1.[email]
FROM [user] t1
WHERE t1.[created_at] >= '2026-01-01' AND t1.[created_at] < '2027-01-01' AND t1.[language] = 'en'
```

```sql MySQL
SELECT t1.`user_id`, t1.`name`, t1.`email`
FROM `user` t1
WHERE t1.`created_at` >= '2026-01-01' AND t1.`created_at` < '2027-01-01' AND t1.`language` = 'en'
```

```sql Postgres
SELECT t1.user_id, t1.name, t1.email
FROM "user" t1
WHERE t1.created_at >= '2026-01-01' AND t1.created_at < '2027-01-01' AND t1.language = 'en'
```

```sql Snowflake
SELECT t1.user_id, t1.name, t1.email
FROM "user" t1
WHERE t1.created_at >= '2026-01-01' AND t1.created_at < '2027-01-01' AND t1.language = 'en'
```

```sql Athena
SELECT t1.user_id, t1.name, t1.email
FROM "user" t1
WHERE t1.created_at >= TIMESTAMP '2026-01-01 00:00:00' AND t1.created_at < TIMESTAMP '2027-01-01 00:00:00' AND t1.language = 'en'
```
</CodeGroup>

The query returns the User_id, Name and Email of each matching user. Notice how Fyno AI interprets the prompt: "signed up in 2026" becomes a date range on `created_at`, and "English" becomes the language code `en` as stored in the data. The table and column names in your query come from the schemas you select, so yours will differ.

<Steps>
  <Step>In the **Use Fyno AI to generate query** field, describe the segment of users you want, including all conditions.</Step>
  <Step>From the **Select relevant schema/s** dropdown, choose the schema or schemas that contain the data your prompt refers to. You can select more than one.</Step>
  <Step>Optionally, select **Let Fyno AI use the first 3 rows of relevant schemas for accuracy**. This gives Fyno AI a sample of your actual data, which helps it understand field formats and values (such as `en` for English) and produce a more accurate query.</Step>
  <Step>Click **Generate Query**. The generated query appears in the **Query Editor**.</Step>
  <Step>Review the query, edit it if needed, and click **RUN** to view the results.</Step>
  <Step>Optionally, rate the query using the thumbs up or thumbs down icon next to **What do you think about this?** Your feedback helps improve Fyno AI.</Step>
</Steps>

<Tip>If the results aren't what you expected, refine your prompt and generate the query again, or edit the query directly in the Query Editor.</Tip>

<Note>Fyno AI only reads the first 3 rows of the selected schemas when you enable the sample-data option. Leave it unchecked if those rows contain sensitive information you don't want to share.</Note>

## Save the cohort

Once the data below the builder shows the users you want, save the cohort:

- Click **Save Cohort** to save it and stay on the cohorts list.
- Click the arrow next to **Save Cohort** and select **Save and Create Campaign** to save the cohort and open the **Create Campaign** pop-up with this cohort already selected.

![](/images/connect_cohort_save_options.png)
