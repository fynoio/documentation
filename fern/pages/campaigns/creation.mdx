## Pre-requisites

To create a Campaign, you will first need to have a few things in place:

- A provider integration in Fyno's platform
- A notification [template](./template-creation) (it may be any channel)
- A Notification [Event](./notification-event-creation)
- A CSV file or xlsx file or Google sheet or Public URL or a Cohort with the user base to whom you would be triggering the campaign.

`Once` we have these in place, we are all set to go with campaigns!

## Creating a Campaign

To create a campaign,

<Steps>
  <Step>Login to your Fyno account and find **Campaigns** from the left navigation bar under 'Advanced' section.</Step>
  <Step>On the landing page of **Campaigns**, click on the 'New Campaign' CTA at the top right corner. It will open a popup as shown below. ![](/images/campaign_new.png)</Step>
  <Step>Enter a name for your **Campaign** and select the notification event you want to fire using this campaign from the dropdown.</Step>
  <Step>Once you have selected the event, you will see the channels linked to that event and also you will see a sample file structure which you need to upload (as shown below). For ex - The selected notification event has only SMS and WhatsApp channel, thats why you see only SMS and WhatsApp channel in the sample file structure. ![](/images/campaign_creation_new.png)</Step>
  <Step>
    You can create a campaign in any of the following ways:
    <ol>
      <li>File upload</li>
      <li>Google sheet</li>
      <li>Public URL</li>
      <li>Cohort</li>
    </ol>
  </Step>
</Steps>

## Creating a campaign using File (CSV/Excel) upload

If you want to create a campaign using csv/excel(.xlsx) upload,

<Steps>
  <Step>You can also download the sample CSV/XLSX file by click 'Download sample file' .</Step>
  <Step>Once you have your CSV/XLSX file ready, click 'Upload file' or Drag and drop the CSV/XLSX from your device. ![](/images/campaign_csv.png)</Step>
  <Step>
    Once the file is uploaded, you will see a few important details: ![](/images/campaign_validate_csv.png)
    <ol>
      <li>Number of records processed</li>
      <li>Number of records ready to be imported</li>
      <li>Number of records that are not valid (as per the checks in place). This could happen if there are any records without any destination and distinct Id etc.</li>
      <li>Number of duplicate records that were found.</li>
      <li>If there are any duplicates present in the csv uploaded and if you still want to include the duplicate data, then select the checkbox 'Include duplicates in campaign'.</li>
    </ol>
  </Step>
  <Step>Click 'Create Campaign' to import the valid records from CSV/XLSX file.</Step>
</Steps>

<Info>If you are using **Distinct IDs**, ensure that this data matches the pre-existing distinct Ids in **User Profiles** on Fyno.</Info>

<Note>If you want to use JSON data, upload it in a pre-defined field **'csv-json-payload'**, and map this column in the campaign to send a placeholder to the event as a JSON object</Note>

## Creating a campaign using Cohort

If you want to create a campaign using Cohort,

<Steps>
  <Step>Select Cohort. You will see the list of requirements. Please make sure all the requirements are satisfied. ![](/images/campaign_cohort.png)</Step>
  <Step>Select a cohort created in the User profile section. To learn more about how to create a cohort, refer this [doc](./creating-cohorts). Click 'Validate Cohort'.</Step>
  <Step>You will see the validation as shown. ![](/images/campaign_cohort_validate.png)</Step>
  <Step>Once all the records are ready to be imported, click 'Create Campaign'.</Step>
</Steps>

<Tip>When 'Include duplicates in campaign' is enabled, any duplicate records in your uploaded file will be processed. This means your users may receive the same communication multiple times. To prevent spam, consider leaving this option disabled.</Tip>

## Configuring Campaign

Once you have uploaded a CSV or linked a CSV using Google sheet or Public url or cohort, you will see the below screen

![](/images/campaign_configure.png)

<Steps>
### Notification Event
The notification event is preselected based on the value selected.

### Map destinations & Placeholders

In this step, you will need to configure the details needed for the event to be successfully triggered. This includes the mapping of the Channels and Placeholders. You can select each item's corresponding data field from the uploaded CSV file by clicking on the drop-down and selecting one. In case you do not want to trigger a notification to a specific channel, you can remove it by deleting that row from this section.
![](/images/campaign_destination.png)
<Warning> Ensure all placeholders are properly mapped to your columns. For WhatsApp specifically, notifications will fail to deliver if any placeholder remains unmapped.</Warning>
### Preview

Preview allows you to visualize how the data from a CSV upload appears within the template, ensuring the uploaded data aligns with your expectations. You will see the preview as shown below. You can click '\<' and '>' to see a preview based on the first 10 records from the uploaded CSV file.
![](/images/campaign_preview_config.png)

</Steps>

### How to enable receiving Delivery reports from Fyno?

To enable receiving delivery reports from Fyno, select the checkbox 'Receive delivery report from Fyno to my allowlisted endpoint(s)'. This enables the callbacks for the channels and essentially sends back the delivery updates about each notification triggered. On checking this box, 3 additional placeholder details will need to be configured.

![](/images/campaign_delivery_report.png)

<ParamField path="Allowlisted Endpoints" type="string" required={false}>
  <ul>
    <li>Specify one or more allowlisted URL names (upto 3) where you want to receive delivery reports.</li>
    <li>If no URL name(s) are specified here, the system will use your default URL (if one exists).</li>
    <li>If no URL name(s) are specified here AND no default URL is set, delivery reports cannot be sent.</li>
    <li>**Example**: `["DynamicWebhookSite", "Mixpanel"]`</li>
    <li>**Example**: `DynamicWebhookSite`</li>
  </ul>
</ParamField>

<ParamField path="Custom ID" type="string" required={true}>
  <ul>
    <li>Unique identifier of your notification</li>
    <li>**Length**: 200 characters if string</li>
    <li>**Length**: 20 digits if numeric</li>
  </ul>
</ParamField>

<ParamField path="Custom Value 1" type="string" required={false}>
  <ul>
    <li>Additional information to tag your notification</li>
    <li>**Length**: 50 characters</li>
    <li>**Example:** `campaign-name`</li>
  </ul>
</ParamField>

<ParamField path="Custom Value 2" type="string" required={false}>
  <ul>
    <li>Additional information to tag your notification</li>
    <li>**Length**: 50 characters</li>
    <li>**Example:** `category`</li>
  </ul>
</ParamField>



More values can be added in the callback. For a list of additional available values, please see: [Callback Response](./allowlist-url#callback-response)

Click **Reset** to reset all the configurations for the Map Channels and Placeholders section.

### How to throttle a campaign?

Throttle is optional but we recommend using it. Throttling allows you to control the rate at which notifications (Emails/SMS/WhatsApp/Push/WebPush) are sent to users.

1. **By Time** - You can specify a duration for which the campaign should run. For example, if you want to execute the campaign for an hour, you can do that by entering 60 minutes.

![](/images/campaign_throttle_time.png)

2. **By Batch** - In this option, you can throttle the number of records the campaign should send for a specific duration. For example you want to send a execute a batch of 1000 records in the csv file every minute, then you can enter 1000 records and 1 minute

![](/images/campaign_throttle_batch.png)

### How to test a campaign?

Just before you send out a campaign to all your customers, running a test is always a good idea, since you will be able to preview the look and feel of your notifications before they go out.

To do this, once you have set up your campaign, simply:

<Steps>
  <Step>Scroll to the top of the campaign configuration page to find the **Run Test** button and click on it.</Step>
  <Step>
    A new pop-up requesting the below information to run the test will come up:
    <ol>
      <li>**Send Using (Channel Details)**: Map the channels that are there in the notification event to run the test on.</li>
      <li>**Map Placeholders**: Map the placeholders that are there in the template of the corresponding Notification event to successfully simulate the notification.</li>
    </ol>
  </Step>
  <Step>Once ready, click on run test to get the notification delivered to the corresponding test recipients.</Step>
</Steps>

### Save as Draft

Once an event is configured with the details of the **Notification Event**, mapped Channels and Placeholders and scheduled time, this can now be saved to use or edit at a later time.

Simply click on the **Save** at any point in time of configuring the campaign and this will be saved for later use!

### How to Fire or Schedule a campaign?

Once you have done with all the configuration, you can click Schedule/Fire CTA. You can fire it in 2 ways.

1. **Now** - If you select Now and click 'Fire', the campaign will be fired immediately and your users will start getting notifications.
2. **Later** - If you select Later, you will be asked to select a date and time when you want to fire the campaign.

![](/images/campaign_schedule.png)

<Info>You can select a date upto 30 days from the time of selecting the schedule.</Info>

Once you have successfully fired a campaign, you can see the progress as shown below.

![](/images/campaign_schedule_later.png)

### How to stop a campaign?

If you want to pause a campaign after its fired, you can click the Stop Campaign and status of the campaign will show as Stopped.

![](/images/bb11765d1f4761d32cbfe1737b01110522793eceb8e2d51e8f5d69d93c2c4c8f-image_34.png)

<Info>Please note that 'Stop Campaign' will be enabled only for CSV with more than 1000 records.</Info>

### How to receive a campaign completion report over workflow?

<Steps>
  <Step>Create a workflow with the name **FynoCampaignCompletionStatus**.</Step>
  <Step>The following payload is accessible in the workflow</Step>
  ```curl title="Trigger workflow with Campaign Status" wordWrap
{
    "type": "campaign-completion-status",
    "status": "success|fail|subfail",
    "upload_id": "UPXXXXXXXX",
    "count": 1XXXX,
    "campaign_name": "Your Campaign Name",
    "process_count": 1XXXX
}

```
  <Step>Configure a Call API widget to post campaign details to your Allowlist endpoint.</Step>
  </Steps>

  ### Payload data

  The following parameters are sent as payload to trigger the workflow **FynoCampaignCompletionStatus**
  
  - Campaign Status
      <ol>
        <li>success : Campaign Successfully Fired.</li>
        <li>fail : Campaign stops during execution due to an unknown error, campaign may execute partially.</li>
        <li>subfail : Campaign executes successfully but All req may not submitted to the provider due to invalid details like destination,distinct_id, integration</li>
      </ol>

  - Upload_id : This is available only if you are using Campaign API to create and trigger a campaign.
  - Count : No of valid records uploaded through campaign. 
  - Process Count : No of records successfully processed. 
  - Campaign name : The name of the campaign for which the status is sent. 
 
## How to re-run a campaign

To re-run a campaign, go to the campaign page and click 'Re-run' at the top right corner. You will see a pop-up as shown. ![](/images/campaign-rerun.png)
- Enter a campaign name
- Select if you want to fire the campaign now or schedule it for later.
- Select the checkbox to confirm the campaign re-run.
- Click 'Confirm'. 

<Note> The campaign re-run will send notifications to the same set of users who was part of the first run. </Note>
