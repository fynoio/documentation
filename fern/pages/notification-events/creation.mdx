A notification event is the single most important part of Fyno's application design.

<Note>
**Notification Event = Template + (Providers or Route)**
</Note>

Before you create a notification event, make sure you have already set up:

1. Providers
2. Templates
3. Routing (optional)

## Create a notification event

To create a new notification event, click **CREATE** on the top right of the Notification Events page.

![Creating a notification event](/images/create-notification-event.gif)

<Steps>
  <Step>Enter a **Name** for your notification event.</Step>

  <Step>
    Select the **Type** from one of the three options:
    - **OTP**
    - **Transactional**
    - **Marketing**
  </Step>

  <Step>
    Select a group in **Add To Group (Optional)**. This helps you keep all related notification events together.
  </Step>

  <Step>
    Add a **Description (Optional)**. This helps you identify and manage the event more easily later.
  </Step>

  <Step>
    Select a subscription topic in **Select Subscription Topic (Optional)**. The list shows the subscription topics created in User Preferences. To learn how to create one, see [User Preferences](./user-preferences).
  </Step>

  <Step>Click **SUBMIT** once you're done.</Step>
</Steps>

<Note>Make sure you choose the correct subscription topic. If a channel is turned off in the subscription topic, notifications will not be sent on that channel, even if a template is set up for it.</Note>

## Template

The first step to building a notification event is to pick a template you have already created in **Templates**, or to create a new one by clicking **Create Template**.

- **Selecting a template**

  - Click the dropdown to see all the templates you have created. Select one to continue.
  - Once you select a template, a preview of it appears on the right side.
  - To edit the selected template, click **EDIT TEMPLATE** just above the template preview on the right side.
    ![](/images/event_select_template.png)

- **Creating a new template**

  - You can create a new template from scratch by clicking **Create Template**.
    ![](/images/event_select_template.png)

  - This opens a popup where you can start creating the template.
  - See [Create a template](./template-creation) to learn how to create a template from scratch.

### Conditional Templates

Conditional Templates let you pick which template to send based on conditions you set. This means you can attach several templates to the same notification event, instead of creating a separate notification event for each one.

#### How does it work?

Say you want to send order updates to users for the statuses Order Confirmed, Shipped, In-Transit and Delivered. You can create four templates, one for each status. With Conditional Templates, all four templates can live under a single notification event, which keeps your setup simple.

<Info>There is no limit on the number of templates you can add to a conditional template flow.</Info>

<Steps>
  <Step>
    Go to the notification event page and click **Use conditionally** under the Templates section.

    ![](/images/event_conditional_template_click.png)
  </Step>
  <Step>
    To add conditions:
    1. Select the template you want to use.
    2. Set conditions based on variables. For example, to send the Order Confirmed message, select the `Order_Confirmed` template and set the condition as "status equals Confirmed". Repeat this for the other statuses. Use **Add rule** to add more than one condition for a template.
    3. Click **Add Template** to keep adding templates with conditions.
    4. Make sure an **Else** condition is added. Choose either **Do Nothing** or a fallback template to send when none of the other conditions match.

    ![](/images/event_conditional_templates.png)
  </Step>
  <Step>To delete a condition, click the delete icon on the right side of that condition.</Step>
  <Step>To preview a template, click the numbered button in the top left corner of the conditional template card. The preview appears on the right side of the page.</Step>
  <Step>To reorder the conditions, drag them up or down using the **Drag Indicator** icon on the left side of each condition.</Step>
  <Step>To remove all the conditions at once, click **Remove all conditions** at the bottom.</Step>
  <Step>
    Once you have added all the conditions, they appear in a collapsed view as shown below. To preview the different templates, click **>** to go forward and **\<** to go back, or type the condition number in the field next to **Previewing** to jump straight to that template.

    ![](/images/event_conditional_templates_collapsed.png)
  </Step>
  <Step>To change any of the conditions, click **Edit Conditions**.</Step>
</Steps>

## Route/Provider

Route/Provider lets you decide how the notification is sent across channels and providers.

Click the dropdown under **Rules** to see these options:

- **Single Channel Route or Provider**: Pick a **Provider** or **Route** for each channel separately. For example, if your template has 3 channels, you will choose how to send your Email, SMS and WhatsApp. For each channel, you can pick a service provider or a Single Channel Route created for that channel. Read more about [Single Channel Routes](./route-creation).
  ![](/images/event_select_single_channel_route.png)

- **Omni-channel Route**: Select an Omni-Channel Route you have already created. Read more about [Omni-Channel Routes](./omnichannel-routing-introduction).

## Analytics Label (Optional)

Use this option to group the analytics of several notification events together, or to filter the analytics of a single notification event.

![](/images/event_analytics_label.png)

You can select either a Static or a Dynamic analytics label.

- **Static**: Use this to combine and view analytics across several related notification events.

  - **Example:** Say you want to track several order status notifications (Confirmed, Shipped, InTransit, Delivered) in one view. You no longer need to check each notification separately, and you get a full picture of how customers engage across the whole order journey. By grouping these notifications, you can see how your Order Status messages perform at a glance.
  - **How to group analytics:**
    - Go to the analytics label dropdown.
    - Select the Order Status notifications you want to view together.
  - **Related resources:**
    - To learn how to add analytics labels, see [Analytics Label](./analytics-label).
    - To learn how to view the analytics, see [Dashboard](./dashboard).

- **Dynamic**: Use this to look closely at how your notifications perform by either:
  - Grouping analytics across several notification events
  - Filtering data for one notification event
  - **Example:** Say you send policy renewal emails using one template for different mobile brands (Apple, Samsung, Vivo and Oppo).
    - How to view analytics by brand:
      - Use the placeholder `{{brand_name}}` as your analytics label.
      - This lets you track how the emails perform for each mobile brand separately.
  - **Related resources:**
    - To learn how to add analytics labels, see [Analytics Label](./analytics-label).
    - To learn how to view the analytics, see [Dashboard](./dashboard).

## Check for Duplication (Optional)

![](/images/event_duplicate_check.png)

This option appears only if the **Duplicate Message Check** setting is turned on. Read how to turn it on in [Duplicate Message Check](./duplicate-message-check).

Turning on this option drops any notification with the **same template ID, channel and destination**. You can also check placeholder values before deciding whether to drop a notification. This makes sure users don't receive the same message twice if it is triggered by mistake from your end.

<Steps>
  <Step>Select the **Check for Duplication** checkbox.</Step>
  <Step>Enter how long to keep checking for duplicates. For example, if you want to drop any repeat of a notification for the next 1 hour after it is sent, enter 1 hour. You can enter up to 24 hours.</Step>
  <Step>Turn on **Exceptions** to check placeholder values before deciding whether to drop a notification. Select the placeholders to check (along with template ID, channel and destination) from the dropdown.</Step>
  <Step>
    **Example scenario**: Say you send SIP confirmation notifications where:
    - A user has several SIPs
    - Each SIP is for a different stock
    - All SIPs have the same amount
    - The only difference is the stock name
  </Step>
  <Step>
    **How to use it:**
    - Turn on **Exceptions**.
    - Select the relevant placeholders from the dropdown (for example, `Stock`).
    - Fyno then takes the stock name into account when checking for duplicates.
    - Result: All the notifications are sent, even though they share the same template, channel and destination.
  </Step>
</Steps>

## Track Conversion (Optional)

This option appears only if the **Conversion Tracking** setting is turned on. Read how to turn it on in [Conversion Tracking](./conversion-tracking).

![](/images/event_track_conversion.png)

<Steps>
  <Step>Select the **Track conversion** checkbox.</Step>
  <Step>Enter how long to track the conversion. For example, if you want to track conversions for 15 minutes after the notification is sent, enter 15 minutes.</Step>
  <Step>Click **Copy Code**. To tell Fyno to mark a notification as **Converted** for a user or destination, you only need to pass the conversion ID in the data payload. Make sure you pass the same conversion ID when you trigger the notification event.</Step>
</Steps>

### Test and Live Versions

Saving a **Test** version does not affect the **Live** version, which may already be connected to your application and in use.

Once you are happy with the notification event you have built and tested in the **Test** version, follow these steps to make it live:

<Steps>
  <Step>Make your final changes to the notification event and test it to make sure you get the results you want.</Step>
  <Step>At the top of the page, next to the notification event name, you will see the Test version.</Step>
  <Step>To keep it as **Test**, click **Save** and the draft is saved.</Step>
  <Step>To make this Test version live, click **Go Live**.</Step>
  <Step>The current version is now the Live version of the notification event.</Step>
</Steps>

## How to group notification events?

Notification event groups help you keep related notification events together. For example, if you have notification events for different order statuses (Confirmed, Cancelled, Shipped, InTransit, Delivered), you can create an "Order Management" group and add all of them to it. This makes filtering and managing notification events easier.

Read more in [Notification Event Groups](./notification-event-group).

## Save & Go Live

Make sure you save every change by clicking **Save** at the top of the page. This saves your changes only to the **Test** version.

When you click **Go Live**, the notification event goes live right away.

<Note>
If [Approval Request](./approval-request) is turned on, clicking **Go Live** asks you to raise an approval request first. See [Approval Request](#approval-request) below.
</Note>

## Approval Request

If Approval Request is turned on in Security Settings, clicking **Go Live** asks you to raise an approval request for your changes.

<Tip>
For the full details on how approval requests work, see [Approval Request](./approval-request).
</Tip>

![Raising an approval request](/images/request-approval.gif)
Click **Go Live**. The **Request Approval** window opens, showing the notification event name and version.
    - Choose one or more approvers in **Select Approvers**. At least one approver is required.
    - Add a short note in **Write a Message** explaining why you are asking for approval.
    - Select **Go live on approval** if you want the notification event to go live as soon as the request is approved.
    - Click **REQUEST** to send the request.

    ![Request Approval window](/images/request-approval.png)
