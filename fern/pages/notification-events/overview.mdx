A notification event brings together a template and the way it is delivered, either through service providers or a route (single channel or Omni-Channel).

<Note>
**Notification Event = Template + (Providers or Route)**
</Note>

## What does it do?

A notification event is what sends your configured message to the end user.

## How does it work?

<Steps>
  <Step title="Add the recipient">
    Add the recipient's phone number or email ID, depending on your use case.
  </Step>
  <Step title="Fill in the variables">
    Add values for the variables created in the template.
    - Variables are usually written inside **`{{}}`**.
    - Fill in every variable. If a variable is left empty, a blank (null) value is sent in place of the placeholder in the message.
  </Step>
</Steps>

## The Notification Events page

Select **Notification Events** from the navigation to see all the notification events in your workspace.

![Notification Events page](/images/listing.png)

From this page you can:

- Search for a notification event by name using the **Search Notification Events** box.
- Filter the list using the **Version** dropdown.
- See all notification events under **All**, or browse them by group under **GROUPS**.
- Create a new notification event using **CREATE**.
- Open the **More Options** menu (⋮) on any notification event card.

Each card shows the notification event name and when it was last updated. The icons at the bottom of the card tell you its version and type:

| Icon | What it means |
| --- | --- |
| Teal rocket | The notification event has a Live version. |
| Grey rocket | The notification event only has a Test version. |
| Shop | Marketing notification event. |
| Dollar sign ($) | Transactional notification event. |
| Asterisks (\*\*\*) | OTP notification event. |

## How to create a notification event

![Creating a notification event](/images/create-notification-event.gif)

<Steps>
  <Step>
    On the Notification Events page, click **CREATE**. The **Create Notification event** window opens.
  </Step>
  <Step>
    Fill in the details below and click **SUBMIT**.
  </Step>
</Steps>

![Create Notification event window](/images/create-dialog.png)

| Field | Required | What to enter |
| --- | --- | --- |
| **Name** | Yes | A name for the notification event. |
| **Type** | Yes | The kind of message this event sends: **OTP**, **Transactional** or **Marketing**. |
| **Add To Group (Optional)** | No | A group to organise notification events for easier management. |
| **Description (Optional)** | No | A short note about what this notification event is for. |
| **Select Subscription Topic (Optional)** | No | The subscription topic this notification event belongs to. |

![Type dropdown](/images/type-dropdown.png)

Next, choose the template along with the channels to complete the notification event. A detailed walk-through is provided in the next section.

## Notification Event Options Menu

Each notification event card has a **More Options** menu (⋮). It gives you quick access to common actions, so you can update, review, copy, delete or publish a notification event without leaving the list.

![More Options menu](/images/options-menu.png)

The available actions are:

- **Edit**: Change the notification event name or its group.
- **Copy to another workspace**: Copy the notification event to a different workspace.
- **View Details**: See where the notification event is used and what it depends on.
- **Duplicate**: Create a copy of the notification event in the same workspace.
- **Delete**: Delete the notification event.
- **Go Live**: Publish the current Test version of the notification event to Live.

### Edit

Use **Edit** to change the notification event's basic information. Its setup (templates, routes and providers) stays as it is.

You can:

- Rename the notification event.
- Move it to a different group.

This is useful when you want to reorganise or rename notification events without touching how they work.

### Copy to another workspace

Use **Copy to another workspace** to reuse a notification event in another workspace without building it again. After the copy is done, the copied notification event can be managed on its own, separately from the original.

For the full steps, see [Copy notification events to another workspace](#copy-notification-events-to-another-workspace) below.

### View Details

**View Details** shows where a notification event is used and what it needs to work. Check this before you make changes, publish or delete a notification event.

![Opening View Details and switching between Live and Test](/images/view-details.gif)

<Tabs>
  <Tab title="Live">
    ![View Details, Live version](/images/view-details-live.png)
  </Tab>
  <Tab title="Test">
    ![View Details, Test version](/images/view-details-test.png)
  </Tab>
</Tabs>

#### What you will see

| Item | What it shows |
| --- | --- |
| **Name** | The notification event name. |
| **Group Tag** | The group the notification event belongs to, such as Internal Alerts or Onboarding. |
| **Test / Live** | Which version you are looking at. |
| **Last Updated** | When the selected version was last changed. |
| **Used in** | The campaigns and workflows that use this notification event, so you can see what is affected if you change or delete it. |
| **Depends On** | The templates, Omni-Channel routes and integrations this notification event uses. |

#### Switch between Test and Live

Use the **Test** and **Live** toggle at the top right to switch between the two versions without leaving the page.

- **Test**: The draft version, used for building and testing before it is published.
- **Live**: The version your end users currently receive.

### Duplicate

Use **Duplicate** to create a copy of a notification event in the same workspace.

<Steps>
  <Step>
    Click the **More Options** menu (⋮) on the notification event and select **Duplicate**. The **Duplicate Notification event** window opens.
  </Step>
  <Step>
    The **Name** is filled in with the original name followed by `-copy`, and the **Type** is carried over. Change them if needed.
  </Step>
  <Step>
    Optionally, choose a group, add a description or select a subscription topic.
  </Step>
  <Step>
    Click **SUBMIT**.
  </Step>
</Steps>

![Duplicate Notification event window](/images/duplicate-dialog.png)

### Delete

Use **Delete** to remove the notification event from the workspace.

Before anything is deleted, Fyno shows the campaigns and workflows that use this notification event, so you can see the impact before you confirm.

<Note>
If [Approval Request](./approval-request) is turned on, the deletion is sent as an approval request instead of happening right away.
</Note>

### Go Live

Use **Go Live** to publish the current Test version of the notification event to Live.

## Copy notification events to another workspace

You can copy notification events from your workspace to other workspaces you own. Copying is only available in workspaces where you have the **Owner** role.

<Warning>
Only the notification event itself is copied. Everything it depends on, such as templates, components, routes and integrations, must be created or copied into the destination workspace separately. If these are missing, the copied notification event will need extra setup before it works.
</Warning>

### 1. Prepare your destination workspace

<Steps>
  <Step>
    Create the required integrations in the destination workspace.
  </Step>
  <Step>
    Go to **Templates** from the navigation and copy the templates used by the notification events. If they use reusable components, copy those too from **Components** under Templates. See the [copy process](./copying-templates-components).
  </Step>
  <Step>
    If applicable, go to **Routes → Single Channel** and **Routes → Omni-Channel** from the navigation and copy the routes used by the notification events. See the [copy process](./copying-routes).
  </Step>
  <Step>
    If the notification events use Analytics Labels, create the labels on the **Add Ons** page.
  </Step>
  <Step>
    If the notification events use Subscription Topics, create and set up the topics on the User Preferences page (**User → Preferences** from the navigation).
  </Step>
</Steps>

### 2. Copy your notification events

![Copying a notification event to another workspace](/images/copy-to-another-workspace.gif)

<Steps>
  <Step>
    Make sure you are in the workspace you want to copy the notification event from.
  </Step>
  <Step>
    Select **Notification Events** from the navigation.
  </Step>
  <Step>
    Click the **More Options** menu (⋮) on the notification event you want to copy and select **Copy to another workspace**.
  </Step>
  <Step>
    A checkbox now appears next to every notification event on the page. Select one or more notification events to copy.
  </Step>
  <Step>
    Click **COPY SELECTED NOTIFICATION EVENT** in the bar above the list. To start over, click **Clear selection**.

    ![Copy selected notification event bar](/images/copy-selected-bar.png)
  </Step>
  <Step>
    Choose which version to copy:
    - **One notification event with a Live version**: You can choose to copy either the latest Live or the latest Test version.
    - **One notification event with only a Test version**: The Test version is copied.
    - **Several notification events**: The latest Live or latest Test version of each is copied, depending on the notification event.
  </Step>
  <Step>
    In the **Destination Workspace(s)** dropdown, select up to five workspaces. You will see every workspace you are a member of, but you can only select the ones where you have the **Owner** role.
  </Step>
  <Step>
    Click **Confirm** to start copying. The copied notification events now appear in all the selected workspaces.
  </Step>
</Steps>

### 3. After copying

<Steps>
  <Step>
    If the copied notification event uses a subscription topic, click the **More Options** menu (⋮) on it, select **Edit**, choose the topic in **Select Subscription Topic**, and click **Update**.
  </Step>
  <Step>
    For every copied notification event, select the templates again (including conditional templates, if any).
  </Step>
  <Step>
    Select the routes and/or integrations again and save the notification event.
  </Step>
  <Step>
    Do the same for other copied items. See the [post-copy checklist for routes](./copying-routes#3-post-copy-to-do).
  </Step>
</Steps>

### How versioning works

Say you are copying a notification event from Workspace A to Workspace B. There are two cases:

| Case | What happens |
| --- | --- |
| The notification event **does not exist** in Workspace B | The copy is created as `v1 (Test)`. |
| The notification event **already exists** in Workspace B | The copy is created as a new standalone version that is neither Test nor Live. For example, if Workspace B has `v1 (Test)`, the copy is created as `v2`. |

In the second case, pick the new version from the version dropdown next to the notification event name. Then click **Save** to make it `v2 (Test)`, or click **Go Live** to make it `v2 (Live)`. This way, existing versions in the destination workspace are never overwritten, and you decide when to save or publish the copy.
