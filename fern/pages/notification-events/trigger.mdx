Once a notification event is created and saved, you can trigger it by sending its cURL request.

From the **Notification Events** page:

<Steps>
### Find the notification event

Find the notification event you want to trigger.

### Open the Playground

You can open the Playground in 2 ways:

- On the notification event page, click **Test** in the top right corner.
- On the notification event card, click the **Run Test** icon (▶) in the bottom right corner.

</Steps>

## Playground

The Playground lets you preview, test and get the code for your notification events, and see detailed logs, all in one place.

![Playground](/images/playground.png)

The Playground has two parts: the settings on the left and the **PREVIEW**, **LOGS** and **CODE** tabs on the right.

![Switching between the Playground tabs](/images/playground-tabs.gif)

### Settings on the left

| Setting | What it does |
| --- | --- |
| **Test / Live** | Choose whether to use the Test or Live version of the notification event. |
| **Notification Event** | Pick the notification event you want to trigger from the dropdown. |
| **Send Using** | Choose how to identify the recipient. See the options below. |
| **Email** (or other channel fields) | The recipient's details for each channel in the notification event. |
| **Placeholder values** | A field for each placeholder in the template, so you can test it with your own values. Use **Search** to find a placeholder quickly. |
| **Receive delivery report from Fyno to my allowlisted endpoint(s)** | Select this to check whether the delivery report reaches your allowlisted URL. See [Receive delivery reports in the Playground](#receive-delivery-reports-in-the-playground). |

**Send Using** options:

- **Distinct ID**: The unique ID of the recipient's user profile. Use this only if you manage Distinct IDs in your user profiles.
- **Destination**: Enter the recipient's details directly, such as their email address or phone number.
- **Both**: The API accepts either the Distinct ID or the recipient's details.

### PREVIEW

The **PREVIEW** tab shows the notification that is about to be sent.

- The template name and its version (for example, **Live: v1**) appear at the top. Click the icon on the right to open the template.
- Click a channel icon on the left to see how the message looks on that channel.
- For Email, use the icon on the right to switch between the mobile and desktop views.

**Preview with Conditional Templates**: If the notification event uses conditional templates, the preview shows which template will be used and why:

- Using Template: "Template_name" (template version)
- because "placeholder" matches the condition

### CODE

The **CODE** tab shows the API request for this notification event, ready to copy into your code.

![CODE tab](/images/playground-code.png)

- Choose **CURL** or **NODEJS** to see the code in that format.
- Click **Copy Code** to copy it.
- Select **Get code with batch send** to get the code for sending to many users at once. See [Use Batch Send](#use-batch-send).

### LOGS

The **LOGS** tab lists the notifications you have triggered, so you can quickly check their status.

![LOGS tab](/images/playground-logs.png)

| Column | What it shows |
| --- | --- |
| **TIMESTAMP** | When the notification was triggered. |
| **TEMPLATE** | The template that was used. |
| **TO PAYLOAD** | The channels it was sent on. |
| **DISTINCT ID** | The recipient's Distinct ID, if one was used. |
| **CONVERSION** | The conversion status, if conversion tracking is on. |

Open a log to see its **Log Details**.

![Opening Log Details and switching tabs](/images/log-details.gif)

![Log Details](/images/log-details.png)

- **TRACE** on the left shows each step of the notification with its time, from **Request Received** to the final status. Click **View response** to see the provider's response.
- **Message ID** and **Request ID** at the top can be copied using the copy icon next to them.
- The tabs on the right show more details:

| Tab | What it shows |
| --- | --- |
| **SUMMARY** | The destination, total recipients, channel, provider, integration, template, notification event and provider message ID. |
| **PLACEHOLDERS** | The placeholder values that were sent. |
| **CONTENT** | The message that was sent. For Email, switch between the preview and the code view. |
| **RESPONSE** | The response from the provider, including the final status. |
| **CURL** | The cURL request for this notification. |

<Note>Each log shows the date until which it is available.</Note>

To learn more, see [Notification Event Logs](./notification-event-logs).

### Copy your All-In-One API

On the **CODE** tab, click **Copy Code** at the bottom right of the code window.

### Test your All-In-One API

Click **TEST NOTIFICATION** at the bottom left of the Playground.

![Sending a test notification](/images/test-notification.gif)

The **Response for** window opens and shows how many notifications were **Submitted**, **Accepted** and **Failed**, along with each channel it was sent on. Click the refresh icon to update the status, or **FIRE AGAIN** to send it again.

![Response window](/images/test-response.png)

### Use Batch Send

**Batch Send** (or batching) lets you use the same notification event API to send messages to many users at once, like a campaign.

On the **CODE** tab, select **Get code with batch send** to get the code that lets this notification event API work as a bulk send API.

<Note>Your API will also have "Bulk" added to it when you use **Batch Send**.</Note>

## How to receive delivery reports

### Receive delivery reports in the Playground

To check delivery reports while testing, select **Receive delivery report from Fyno to my allowlisted endpoint(s)** in the Playground and fill in the fields below. Click **READ DOCS** to open this section.

![Delivery report settings](/images/delivery-report.png)

| Field | What to enter |
| --- | --- |
| **Delivery Report Endpoint** | Select up to 3 endpoints where you want to receive delivery reports. |
| **Custom ID** | An identifier for your notification. |
| **Custom 1 (Optional)** | Extra information to tag your notification. It should be added in the allowlist delivery report configuration. |
| **Custom 2 (Optional)** | Extra information to tag your notification. It should be added in the allowlist delivery report configuration. |
| **Custom 3 (Optional)** | Extra information to tag your notification. It should be added in the allowlist delivery report configuration. |

### Receive delivery reports through the API

To receive delivery reports in your system or any third-party tool, send the [callback](./delivery-callback-logs) object in the API call as shown below:

```curl title="Receive delivery reports in callback" wordWrap
{
   "event": "YOUR_EVENT_NAME",
   "to": { // your channel destination },
   "data": {  // your template placeholders  },
   "callback": {
       "enable":true,
       "custom_id": "YOUR_CUSTOM_ID_VALUE",
       "custom1": "YOUR_CUSTOM_VARIABLE_1",
       "custom2": "YOUR_CUSTOM_VARIABLE_2",
       "custom3": "YOUR_CUSTOM_VARIABLE_3",
       "allowlist_url": ["DynamicWebhookSite", "Mixpanel"]
    }
}
```

<Note>The `custom_id`, `custom1`, `custom2` and `custom3` values can be sent back to your allowlisted URL.</Note>

<ParamField path="custom_id" type="string" required={true}>
  <ul>
    <li>Unique identifier of your notification</li>
    <li>**Length**: 200 characters if string. No special characters allowed.</li>
    <li>**Length**: 20 digits if numeric</li>
  </ul>
</ParamField>

<ParamField path="custom1" type="string" required={false}>
  <ul>
    <li>Extra information to tag your notification</li>
    <li>**Length**: 50 characters. No special characters allowed.</li>
    <li>**Example:** `order-id`</li>
  </ul>
</ParamField>

<ParamField path="custom2" type="string" required={false}>
  <ul>
    <li>Extra information to tag your notification</li>
    <li>**Length**: 50 characters. No special characters allowed.</li>
    <li>**Example:** `category`</li>
  </ul>
</ParamField>

<ParamField path="custom3" type="string" required={false}>
  <ul>
    <li>Extra information to tag your notification</li>
    <li>**Length**: 50 characters. No special characters allowed.</li>
    <li>**Example:** `message-id`</li>
  </ul>
</ParamField>

<ParamField path="enable" type="enum" required={false} default="true">
  <ul>
    <li>**true**: Send delivery status through the callback.</li>
    <li>**false**: Don't send delivery status through the callback.</li>
    <li>The default value is **true** if `custom_id` is given.</li>
  </ul>
</ParamField>

<ParamField path="allowlist_url" type="string" required={false}>
  <ul>
    <li>Give one or more allowlisted URL names (up to 3) where you want to receive delivery reports.</li>
    <li>If no URL names are given here, your default URL is used (if you have one).</li>
    <li>If no URL names are given here AND no default URL is set, delivery reports can't be sent.</li>
    <li>**Example**: `["DynamicWebhookSite", "Mixpanel"]`</li>
    <li>**Example**: `DynamicWebhookSite`</li>
  </ul>
</ParamField>
