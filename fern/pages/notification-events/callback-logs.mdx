Delivery Callback Logs help you track every delivery report Fyno sends back to your [allowlisted URL](./allowlist).

On the page, you will see:

- The delivery callback logs
- Filters
- **Test** and **Live** version tabs

## Delivery Callback Logs

The **Delivery Callback Logs** page lists every delivery callback sent to your allowlisted URLs. Each log shows:

| Column | What it shows |
| --- | --- |
| **Timestamp** | The date and time the delivery report was sent to the allowlisted URL. |
| **Notification Event** | The notification event the callback was sent for. |
| **Allowlist URL** | The allowlisted URL the delivery report was sent to. You can see your allowlisted URLs under **Workspace Settings → Allowlist URL**. |
| **HTTP Status Code** | The HTTP status code of the callback request. This can be a success code (such as 200, 201 or other 2xx codes) or a failure code (4xx or 5xx). |
| **Response Time** | How long it took to send the delivery report to the allowlisted URL. |

![Delivery Callback Logs](/images/fb7ca5c-Delivery_Callback_Logs.png)

## Filters

You can filter the logs by:

| Filter | What it does |
| --- | --- |
| **Timestamp** | Shows logs from a time period: **Today**, **Yesterday**, **Last 7 days** or **Custom**. With **Custom**, you can pick any range within your log retention period for delivery callback logs, set under **Workspace Settings → Add On's → Logs Archival**. |
| **Message Id** | The unique ID created for the notification event that was triggered. |
| **Custom Id** | The Custom ID set in the callback. |
| **Allowlist URL** | The allowlisted URL the delivery report was sent to. |
| **HTTP Status Code** | The HTTP status code of the callback request, success (2xx) or failure (4xx or 5xx). |

Click a callback log to see the request and response payloads for that callback.

![Callback log details](/images/096c8af-Callback_details_new.png)

## Test and Live versions

**Test** and **Live** logs are kept separate. Each tab shows only the callbacks for notifications sent in that version.

<Tip title="Can't find a callback log?">Check which environment the notification was triggered in. Callbacks for notifications triggered in **Test** don't appear in **Live**, and the other way round.</Tip>

## How to retry failed callbacks

By default, Fyno tries to send each delivery callback 3 times.

If a callback still fails after that, for example because your server was down, you can resend it with the **Retry Failed Callback** button.

![Retry Failed Callback](/images/delivery_callback_retry.png)

When you click it, a popup shows how many delivery callbacks failed, based on the filters you selected. Click **Retry** to resend all of them.
