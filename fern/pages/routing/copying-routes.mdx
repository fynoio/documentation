Single channel and omni-channel routes can be copied from your workspace to other workspaces you own. 

<Callout type="warning">
  **Prerequisite:** The copy process is only available in workspaces where you have the **Owner** role.
</Callout>

## Steps to copy routes to another workspace

### 1. Prepare your destination workspace

It is important to note that when copying routes, only the route-related data will be copied to the destination workspace. Any dependencies must be created or copied manually in the destination workspace.

<Steps>
  <Step>Manually create the required integrations used by the routes in the destination workspace.</Step>
  <Step>If the omni-channel route contains a single channel route, ensure that the single channel route is first copied over using the process described in the next section.</Step>
</Steps>

### 2. Copy your routes to another workspace

<Steps>
  <Step>Ensure you are in the workspace from where you would like to copy the route.</Step>
  <Step>Navigate to the listing page for single channel routes (**Routes** → **Single Channel** from the navigation) or omni channel routes (**Routes** → **Omni-Channel**).</Step>
  <Step>Click the "Three Dots" icon (**⋮**) on the route that you would like to copy to open the action menu.</Step>
  <Step>
    From the menu options, select **Copy to another workspace**.
    
    ![Options menu showing Copy to another workspace action](/images/workspace-copy/options-menu.png)
  </Step>
  <Step>You will now see a checkbox next to every route listed on the page. You can select multiple routes to copy if needed.</Step>
  <Step>Once you have completed your selection, click **Copy Selected Single Channel Routes** or **Copy Selected Omni Channel Routes** in the alert banner above the listing.</Step>
  <Step>When copying a single route that has both a live and test version, you will see an option to choose which version to copy. If your route only has a test version, that version will be copied automatically.</Step>
  <Step>When copying multiple routes, the latest available version (Live or Test) of each route is copied automatically.</Step>
  <Step>You will see a dialog box with a **Destination Workspace(s)** dropdown menu. This list displays all workspaces you belong to, but only those where you hold the **Owner** role will be active. You can select up to five destination workspaces.</Step>
  <Step>Once all the workspaces are selected, click **Confirm** to initiate the copy process.</Step>
  <Step>The copied routes will now appear in all the selected destination workspaces.</Step>
</Steps>

### 3. Post-copy to-do

Once the routes are copied to the destination workspaces, open each route, re-select the integration (where applicable), and save the route to ensure that it functions correctly.

## How versioning works

Let's say you are copying a route from Workspace A to Workspace B. The versioning behavior depends on whether the route already exists in the target environment:

<Steps>
  <Step>
    **When the route does not exist in Workspace B:** The version created by the copy process will always be initialized as `v1 (Test)`.
  </Step>
  <Step>
    **When the route already exists in Workspace B:** The copy process will create a new standalone version without modifying or overwriting existing versions. For example, if the version in Workspace B is currently `v1 (Test)`, the process will create a new version called `v2`. 
    
    You can select this new version from the version dropdown beside the route name and:
    * Click **Save** to make it `v2 (Test)`.
    * Click **Go Live** to promote it to `v2 (Live)`.
  </Step>
</Steps>
