Campaigns let you send notifications to a group of users without any technical effort. In this tutorial, you will:

1. Create a campaign and upload a file of recipients.
2. Map destinations and placeholders, and configure optional settings.
3. Test the campaign.
4. Fire the campaign now or schedule it for later.
5. Monitor the campaign with logs and analytics.

The example in this tutorial sends a festive offer over WhatsApp and Email, but the same steps apply to any channel.

## Prerequisites

Before you create a campaign, make sure you have:

- An **integration** with a provider for each channel you want to use.
- A **live template** for the notification you want to send.
- A **live notification event** that uses that template. The campaign can use only the channels configured in that event. To learn more, see [Notification Events](https://fyno.io/docs/events-overview), or [Creating a Notification Event](https://fyno.io/docs/notification-event-creation) if you don't have one yet.
- A **CSV or XLSX file** with the recipients' destinations (for example, phone numbers or email addresses) and a value for each placeholder in the template.

## Open Campaigns

From the left navigation, click **Campaigns**. The Campaigns page lists all your campaigns.

| Column | Description |
| --- | --- |
| Campaign Name | The name of the campaign. |
| Group | The group the campaign belongs to. |
| Total Count | The number of records in the campaign. |
| Status | The campaign's current status, for example **Draft** or **Completed**. |
| Updated | When the campaign was last updated. |
| Created By | The user who created the campaign. |
| Channels | The channels the campaign sends on. |
| Fire Time | When the campaign was fired or is scheduled to fire. |

## Create a Campaign

<Steps>

<Step>
<p>Click <strong>+ New Campaign</strong> in the top-right corner.</p>
<Frame caption="New Campaign">
  <img src="/images/new-campaign.png" alt="New Campaign" />
</Frame>
</Step>

<Step><strong>Campaign Name</strong> — Enter a name for the campaign.</Step>

<Step>
<p><strong>Select a live notification event</strong> — Choose the notification event to send. Only live events appear in the list. For more details, see <a href="https://fyno.io/docs/events-overview">Notification Events</a>.</p>
<p>Once you select an event, the <strong>This campaign can be sent via</strong> section shows the channels the campaign will use.</p>
</Step>

<Step>
<p><strong>Create a campaign using</strong> — Select <strong>File Upload</strong>.</p>
<p>This is how you provide the recipient data. Campaigns can also be created from a Google Sheet, a public URL, or a cohort. This tutorial covers file uploads.</p>
<Frame caption="Campaign Detail">
  <img src="/images/new-campaign-detail.png" alt="Campaign Detail" />
</Frame>
</Step>

<Step>
<p>Review the file requirements:</p>
<table>
<thead><tr><th>Requirement</th><th>Details</th></tr></thead>
<tbody>
<tr><td>File type</td><td><code>.csv</code> or <code>.xlsx</code> only.</td></tr>
<tr><td>File size</td><td>Up to 200 MB.</td></tr>
<tr><td>Placeholder names</td><td>Case sensitive. They must match the placeholders in the template.</td></tr>
<tr><td>Links</td><td>Must not be shortened.</td></tr>
</tbody>
</table>
<p>The tabs below the requirements show the expected columns for each channel in the event.</p>
</Step>

<Step>Click <strong>Download Sample File</strong> to get a file with the correct headers, then fill in your recipient data. Keep the headers unchanged.</Step>

<Step>Drag and drop your file into the upload area, or click <strong>Upload File</strong>.</Step>

<Step>
<p>Fyno validates the file and shows a summary:</p>
<table>
<thead><tr><th>Metric</th><th>What it means</th></tr></thead>
<tbody>
<tr><td>Records processed</td><td>Total rows read from the file.</td></tr>
<tr><td>Records can be imported</td><td>Rows that passed validation.</td></tr>
<tr><td>Invalid records</td><td>Rows that failed validation and will not be sent.</td></tr>
<tr><td>Duplicate records</td><td>Rows that repeat another row.</td></tr>
</tbody>
</table>
<p>Duplicates are excluded by default. Select <strong>Include duplicates in campaign</strong> if you want to send to them too.</p>

</Step>

<Step>Click <strong>Submit</strong>. The campaign is created and opens on its configuration page.</Step>

</Steps>

## Configure the Campaign

The configuration page shows the selected notification event, the template it uses, and the uploaded file with the number of unique records and duplicates. Click the download icon next to the file to download it again.

<Frame caption="Configure the Campaign">
  <img src="/images/campaign_config_redacted.png" alt="Configure the Campaign" />
</Frame>

Under **Map Data**, map the columns in your file to the fields the campaign needs.

<Steps>

<Step>
<p><strong>Destinations</strong> — Select the file column that holds the destination for each channel. For example, map SMS to the <code>sms</code> column and Email to the <code>email</code> column.</p>
<p>The number next to <strong>Destinations</strong> shows how many channels the notification event uses. Each channel gets its own row.</p>
<Frame caption="Mapping destinations to file columns">
  <img src="/images/map-data-destinations.png" alt="Destinations mapped to sms, rcs, whatsapp, and email columns" />
</Frame>
</Step>

<Step>
<p><strong>Placeholders</strong> — Select the file column that holds the value for each template placeholder. Every placeholder must be mapped. Click <strong>Add Placeholder</strong> to map an additional placeholder.</p>
<p>The number next to <strong>Placeholders</strong> shows how many placeholders the template uses. In this example, the template has two placeholders, <code>brand</code> and <code>name</code>, mapped to file columns with the same names.</p>
<Frame caption="Mapping placeholders to file columns">
  <img src="/images/map-data-placeholders.png" alt="Placeholders brand and name mapped to file columns" />
</Frame>
</Step>

<Step>
<p><strong>Custom Parameters</strong> (optional) — Expand <strong>Custom Parameters</strong> to map a custom ID and up to three custom values from your file, based on your requirements. Hover over the help icon for more information.</p>
<table>
<thead><tr><th>Field</th><th>Maximum length</th><th>Characters not allowed</th></tr></thead>
<tbody>
<tr><td>Custom ID</td><td>200 characters</td><td><code>&lt;</code> <code>&gt;</code> <code>/</code> <code>"</code> <code>'</code> <code>&amp;</code></td></tr>
<tr><td>Custom Value 1</td><td>50 characters</td><td><code>&lt;</code> <code>&gt;</code> <code>/</code> <code>"</code> <code>'</code> <code>&amp;</code></td></tr>
<tr><td>Custom Value 2</td><td>50 characters</td><td><code>&lt;</code> <code>&gt;</code> <code>/</code> <code>"</code> <code>'</code> <code>&amp;</code></td></tr>
<tr><td>Custom Value 3</td><td>50 characters</td><td><code>&lt;</code> <code>&gt;</code> <code>/</code> <code>"</code> <code>'</code> <code>&amp;</code></td></tr>
</tbody>
</table>
</Step>

<Step>
<p><strong>Send data to my allowlisted endpoint(s)</strong> (optional) — To receive this campaign's data at an allowlisted endpoint, select this option and choose the endpoint to use.</p>
</Step>

<Step>
<p><strong>Throttle</strong> (recommended) — Throttling improves deliverability by controlling the rate at which notifications are sent. Click <strong>Add</strong>. Fyno shows the number of records available to send, then choose how to control the rate:</p>
<table>
<thead><tr><th>Option</th><th>How it works</th></tr></thead>
<tbody>
<tr><td>Time</td><td>In <strong>Run this campaign for</strong>, enter how long the campaign should run, between 15 and 180 minutes. Fyno shows approximately how many records will be processed per minute. For example, 71,966 records over 152 minutes is about 474 records per minute.</td></tr>
<tr><td>Batch</td><td>Control the rate by sending notifications in batches.</td></tr>
</tbody>
</table>
<p>The actual run time may vary depending on the number of records in the file and the throttle limit set in your provider account. To turn throttling off, click <strong>Remove</strong>.</p>
<Frame caption="Throttling by time">
  <img src="/images/throttle-time.png" alt="Throttle set to run the campaign for 152 minutes" />
</Frame>
</Step>

</Steps>

### Preview the Campaign

Once everything is configured, use the preview panel on the right to review the campaign before you fire it. The preview uses data from your file. It shows the template in use and the current record's destination.

- Click a channel icon to switch between channel previews.
- Use the **‹** and **›** arrows to step through sample records from the file.

## Test the Campaign

Run a test before firing the campaign to make sure everything is configured correctly.

<Steps>

<Step>At the top of the configuration page, click <strong>Run Test</strong>.</Step>

<Step>
<p>In the <strong>Test Live Notification Event</strong> popup, enter:</p>
<table>
<thead><tr><th>Field</th><th>What to enter</th></tr></thead>
<tbody>
<tr><td>Destinations</td><td>A test destination for each channel you want to test. Leave a channel blank to skip it.</td></tr>
<tr><td>Placeholders</td><td>Sample values used to fill the dynamic content in your template.</td></tr>
</tbody>
</table>
</Step>

<Step>Click <strong>Test Event</strong> to send the test notification.</Step>

</Steps>

## Save as Draft

Click **Save** at any point to save your configuration. Saved campaigns appear on the Campaigns page with the **Draft** status, and you can edit them before firing.

## Fire or Schedule the Campaign

<Steps>

<Step>Click <strong>Schedule / Fire</strong>.</Step>

<Step>
<p>In the <strong>Schedule Campaign</strong> popup, choose when to send:</p>
<table>
<thead><tr><th>Option</th><th>What it does</th></tr></thead>
<tbody>
<tr><td>Now</td><td>Fires the campaign immediately.</td></tr>
<tr><td>Later</td><td>Schedules the campaign for a date and time within the next 30 days.</td></tr>
</tbody>
</table>
</Step>

<Step>
<p>Click <strong>Fire</strong>, then click <strong>Confirm</strong> in the <strong>Fire Confirmation</strong> popup.</p>
</Step>

</Steps>

## Stop or Re-run a Campaign

After a campaign is fired, the configuration page shows two new buttons:

| Button | What it does |
| --- | --- |
| **Stop Campaign** | Stops a running campaign. Available only for campaigns with more than 1,000 records. |
| **Re-run** | Sends the campaign again. |

## View Logs and Analytics

Once a campaign has completed, open it to find the **Logs** and **View Analytics** buttons at the top of the page. You can also open analytics by clicking the bar chart icon next to the campaign on the Campaigns page.

### Sent Logs

Click **Logs** to open the Sent Logs screen. It shows a table of every notification the campaign sent, with its entry type, status, destination, and message count. To download the data, click **Export Logs** in the top-right corner.

### Analytics

Click **View Analytics** to see the campaign date and a breakdown of how the campaign performed.

#### Summary

| Metric | What it shows |
| --- | --- |
| Events Fired | The number of times the notification event was triggered, split into delivered, undelivered, and dropped. |
| Notifications Requested | Notifications Fyno was asked to send. |
| Notifications Sent | Notifications submitted to providers. |
| Notifications Delivered | Notifications that reached recipients, with the delivery rate. |
| Unique Recipients | The number of unique destinations per channel. |
| Sent by Channels | How many notifications went out on each channel. |

#### Channel Engagement

Shows a channel-level engagement funnel with these statuses:

| Status | Meaning |
| --- | --- |
| Submitted | Sent from Fyno. |
| Delivered | Reached the destination. |
| Read/Open | Read on WhatsApp or In-App, or opened for Email. |
| Clicked | The recipient interacted with the notification. |

You can switch between counts and percentages, and filter statuses using the graph legend.

#### Delivery Distribution

Shows how notifications were delivered or failed across channels. Undelivered statuses include:

- Invalid Subscriber
- Blacklist
- Rejected
- Bounce

Click **Status Guide** on the analytics page for definitions of every status.

#### Request a Report

Click **Request Report** to receive a detailed report link by email and in-app notification. The report includes:

| Field | Description |
| --- | --- |
| `Request_ts` | Timestamp of the request. |
| `Request_id` | Unique ID of the request. |
| `Template` | Template used for the notification. |
| `Distinct_id` | Unique ID of the recipient. |
| `SMS_credits_use` | SMS credits consumed. |
| `Email_credits_use` | Email credits consumed. |
| Channel submission statuses | Submission status for each channel. |
| Channel final delivery statuses | Final delivery status for each channel. |
| Channel delivery history | Full delivery history for each channel. |
