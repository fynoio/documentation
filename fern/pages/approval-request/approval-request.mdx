Approval Requests add a review step before a change affects live traffic. Instead of going live right away, the change goes to designated approvers, who decide whether it should proceed. Every request is tracked, so critical changes are reviewed, intentional and auditable.

Use Approval Requests to:

- Prevent accidental or unauthorized changes.
- Make sure the right people review critical updates.
- Keep teams consistent and accountable when several people can change live configurations.
- Reduce risk when changes affect live users.

## Approvals off vs on

| | Approvals off | Approvals on |
| --- | --- | --- |
| **When you click Go Live** | The change is applied immediately. | An approval request is created. |
| **Who reviews it** | No one. | The approvers you select. |
| **When live traffic is affected** | Right away. | Only after the request is approved. |

<Note>
Approval Requests are **off** by default. Turn them on separately for each feature you want to review.
</Note>

## Supported features

You can turn on approvals for any of these features, independently:

- **External Templates**: see the pages for [WhatsApp](./external-templates/whatsapp/create-approval-request) and [SMS](./external-templates/sms/create-approval-request).
- **Templates**
- **Notification Events**
- **Workflows**
- **Routes**
- **Components**
- **Campaigns**

## How it works

<Steps>
<Step title="A user makes a change">

The user changes a feature that has approvals turned on, and clicks **Go Live**.

</Step>
<Step title="An approval request is created">

Instead of going live, the change becomes an approval request. The user selects approvers, adds a message and submits it.

</Step>
<Step title="Approvers review the request">

Each selected approver approves or rejects the request.

</Step>
<Step title="The outcome is applied">

The request is complete once it has enough approvals, or as soon as one approver rejects it. If approved, the change goes live automatically or is published manually, depending on how the request was set up.

</Step>
</Steps>

## Set up approvals

You manage approvals in two places: **Team Settings**, where you choose who can approve, and **Approval Settings**, where you choose what needs approval.

<Steps>
<Step title="Assign approvers in Team Settings">

On the **Team Settings** page, you can see all team members and their roles. Give approval permissions to the people who should review changes, or remove them.

Approvers can only be added or removed here. Everyone with approval permissions appears in **Approval Settings** as an available approver.

</Step>
<Step title="Open Approval Settings">

On the **Approval Requests** page, open **Approval Settings**.

![](/images/team-approval-settings.png)

The **Approvers** section lists everyone with approval permissions, with their name, email and avatar, and the total count.

</Step>
<Step title="Turn on approvals for each feature">

In the **Modules** section, turn on the toggle for each feature that needs approval. In **Approvals Required**, choose how many approvals a request needs, from 1 to 5.

The highest number you can choose depends on how many approvers you have in **Team Settings**.

</Step>
<Step title="Save">

Click **Save**. Approval rules only apply once they're saved. Click **Cancel** to close without saving.

</Step>
</Steps>

## How approvals are counted

- You can send a request to more approvers than the minimum.
- Any approvers who together meet the minimum can approve it.
- A single rejection rejects the whole request.

![](/images/approval-request-message-final.png)

<Info title="Example">
**Approvals Required** is set to **2**, and a request is sent to **5** approvers. Any **2** approvals approve the request, but any **1** rejection rejects it.
</Info>

## Review approval requests

The **Approval Requests** page shows every request and its status. All approval activity is tracked here.

![](/images/approval-request-main-page.png)

| Tab | What it shows |
| --- | --- |
| **Open** | Requests waiting for action. |
| **Approved** | Requests that met the approval requirements. |
| **Rejected** | Requests that were rejected. |
| **Closed** | Requests that are complete. |

Use **Search** to find a request by name, or filter by **Feature** or **Request Type**.

### Act on a request

<Tabs>
<Tab title="Approve">

Confirms the change is acceptable and counts toward the required approvals. The change is only published automatically if that was chosen when the request was created.

![](/images/approval-request-pop-up-window.png)

</Tab>
<Tab title="Reject">

Rejects the request immediately. The change doesn't go live.

![](/images/reject-approval-request-pop-up-window.png)

</Tab>
<Tab title="Cancel">

Available to the person who created the request. Withdraws the request at any time before it's complete.

![](/images/cancel-approval-request.png)

</Tab>
</Tabs>

## What happens after approval

Approval doesn't always mean the change goes live immediately. The requester chooses this when they create the request.

| Go live on approval | What happens |
| --- | --- |
| **On** | The change is published automatically once it has enough approvals. |
| **Off** | The request is approved, but the change stays unpublished. The requester can publish it manually. |

## Example: approving a template change

<Steps>
<Step title="Turn on approvals">

An admin gives approval permissions to team members in **Team Settings**, turns on approvals for **Templates**, and sets **Approvals Required** to **2**.

</Step>
<Step title="Make a change">

A user edits a template and clicks **Go Live**. Because approvals are on, the template doesn't go live yet.

</Step>
<Step title="Create the approval request">

The user selects approvers, adds a message explaining the change, chooses whether the template should go live automatically on approval, and submits the request.

</Step>
<Step title="Approvers review it">

The request needs at least **2** approvals. If any approver rejects it, it's rejected immediately.

</Step>
<Step title="See the outcome">

- **Approved:** The template goes live automatically if that was chosen. Otherwise, the user publishes it.
- **Rejected:** The template stays unchanged, and the request is marked **Rejected**.

</Step>
</Steps>
