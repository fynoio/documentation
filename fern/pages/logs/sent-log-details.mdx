Log Details provide a granular breakdown of each notification instance, detailing processing time frames, payload components, raw provider responses, and the definitive status of your message delivery path. 

This view is essential for debugging delivery failures and optimization loops when creating routing pipelines for an Event.

![](/images/log_detail.png)

To access the **Log Details** inspector pane, navigate to the **Sent Logs** panel and click directly on any individual transaction row.

### Log Metadata Sections

Each log entry breaks down into dedicated tracking tabs providing high-fidelity transparency for auditing:

1. [Trace](./log-details-trace) – Core chronological routing timeline across internal systems.
2. [Summary](./log-details-summary) – Snapshot overview of event variables, timing, and provider profiles.
3. [Placeholders](./log-details-placeholders) – Variable payload bindings matched to the client API schema request.
4. [Content](./log-details-content) – Rendered visual layout strings transmitted downstream.
5. [Response](./log-details-response) – Synchronous API acknowledgment codes returned by provider endpoints.
6. [Delivery](./log-details-delivery) – Asynchronous webhook statuses mapped directly back by carrier receipts.
