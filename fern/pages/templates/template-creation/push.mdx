When you add the **Push** channel to a template, the **Create your Push Template** screen opens. The Preview on the right shows how the notification looks on a device.

![](/images/pushcreate-v2-editor.png)

## Create a push template

<Steps>
<Step title="Title (optional)">

Enter the push notification title. It helps summarize the notification and give it context.

</Step>
<Step title="Content">

Enter the body of the notification. This is a required field. You can add placeholders within `{{ }}`.

</Step>
<Step title="Buttons (optional)">

Click **Add Button** to add an action button. For each button, enter:

- **Button**: The button text.
- **Link**: Where clicking the button takes the user. Enter a valid HTTP or HTTPS URL, a deeplink, or a route starting with `/` to route the user within the same path.

Use the delete icon to remove a button.

<Note>
Buttons can only be used with Fyno Push, Xiaomi Push and OneSignal Push.
</Note>

</Step>
<Step title="Platform, other settings and additional data (optional)">

Expand **Platform Settings**, **Other Settings** or **Additional Data** to configure them. See the sections below.

</Step>
</Steps>

<Tip>
To use any user property in your templates, add it in this format: `{{$user.$<user_property>}}`. For example, to add Name as a placeholder from the User profile, add it as `{{$user.$name}}`.
</Tip>

<Warning>
You cannot use only numeric values as placeholder keys.
</Warning>

## Platform Settings (optional)

Choose the **Android** or **iOS** tab to set platform-specific options.

<Tabs>
<Tab title="Android">

![](/images/pushcreate-v2-platform-android.png)

| Field | What it does |
| --- | --- |
| **Image URL** | URL of an image that is downloaded on the device and shown in the notification. You can also upload an image. Supported file formats are JPEG, PNG and BMP. WebP and HEIF support varies across platforms. |
| **Destination Url** | Clicking the notification redirects the user to the HTTPS link or deeplink provided here. |
| **Icon** | Name of the icon file stored in your app's drawable resources. |
| **Icon Background Color** | Hex code of the background color around the small icon. |
| **Notification Sound** | Filename of a sound resource bundled in the app. If it is not set, the device's default sound plays. Allowed formats are .wav, .aiff and .caf. Don't include the file extension. |
| **Notification Badge** | The number of items this notification represents. It may be shown as a badge count on launchers that support badging. |
| **Tag** | Only the latest notification with the same Tag ID is shown on the device. Use the same ID to update an existing notification instead of showing a new one. Maximum 64 characters. |
| **Ticker** | Text sent to accessibility services, and displayed in the status bar when the notification first arrives. |
| **Collapse Key** | An identifier of a group of messages that can be collapsed, so that only the last message is sent when delivery can be resumed. |
| **Channel ID** | Adds this notification to a predefined channel ID to categorize it, so users only receive the types of messages they've opted in for. |

</Tab>
<Tab title="iOS">

| Field | What it does |
| --- | --- |
| **Image** | URL of an image that is downloaded on the device and shown in the notification. Supported file formats are JPEG, PNG and BMP. WebP and HEIF support depends on the recipient's device. |
| **Subtitle** | Additional information that explains the purpose of the notification. |
| **Icon** | The icon shown in the top status bar and to the left of the notification text, unless a large icon is set. A bell icon is shown by default. Don't include the file extension. |
| **Sound** | The name of a sound file in your app's main bundle or in the Library/Sounds folder of your app's container directory. Enter `default` to play the system sound. |
| **Badge** | The number to show in a badge on your app's icon. Enter `0` to remove the current badge, if any. |
| **Collapse Key** | An identifier of a group of messages that can be collapsed, so that only the last message is sent when delivery can be resumed. |

</Tab>
</Tabs>

## Other Settings (optional)

![](/images/pushcreate-v2-other-settings.png)

| Field | What it does |
| --- | --- |
| **TTL** | How long the push message is preserved for delivery if the device is offline. Enter the value in the first field and select the unit of time, such as **Seconds**, in the second. |
| **Analytics Label** | A label to track the analytics of this push template in Google Analytics. |
| **Priority** | The priority of the message sent to devices, for example **Normal**. Priority controls when the message is delivered. |

## Additional Data (optional)

Use **Additional Data** to send extra information with the notification, for example to render something on the device or to send a data (payload) push notification. If you use event listeners instead of deeplinks, add a payload your app can use for redirection.

![](/images/pushcreate-v2-additional-data.png)

Enter the data as JSON. Placeholders in additional data must be inside double quotes, in the format `"{{ }}"`. For example:

```json
{
  "screen": "order_details",
  "order_id": "{{order_id}}"
}
```

## How to test a push template

Use this feature to test a template thoroughly before including it in any Notification Event. This ensures early detection and resolution of any potential issues, for a seamless user experience.

<Steps>
<Step>

Click **Run Test** at the top right of the template. The test pop-up opens.

![](/images/template_push_test_updated.png)

</Step>
<Step>

Enter either the push token of the recipient where the notification should be sent, or a `distinct_id`. **Make sure to enter the distinct_id of a Test User profile.**

</Step>
<Step>

Select a push integration that is already configured in Fyno.

</Step>
<Step>

Click **Test** to send the push notification to the recipient with the selected integration. You see the success or failure message along with a link to the Sent Logs.

</Step>
</Steps>

## Save and go live

Click **Save** to save the template as a **Test** version. You can save different versions of the template this way. Use **Go Live** when you are ready to move your template to the **Live** version.

<Note>
If your workspace has a maker-checker workflow enabled for template management, **Go Live** needs an additional approval step. Choose from your designated approvers, who review and authorize the template changes. See [Approval flow](./approval-flow) for the steps.
</Note>
