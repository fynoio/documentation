When you add the **Voice** channel to a template, the **Create your Voice Template** screen opens. First choose the **Type** of call, then configure it. Because Fyno works with many voice providers, some types also need setup in your provider's platform. See [Provider-specific setup](#provider-specific-setup).

| Type | What it does |
| --- | --- |
| [IVR](#ivr) | Uses the IVR info configured on the provider's portal. |
| [Call Connect](#call-connect) | Connects your bridge number and the recipient, on each leg of the call. Also used for call masking. |
| [Text to Speech](#text-to-speech) | The typed text is spoken out when the call is connected. |

## Create a voice template

<Tabs>
<Tab title="IVR">

### IVR

The IVR configured on your integration page is used to run the call.

![](/images/voicecreate-v2-ivr.png)

<Steps>
<Step title="Select IVR">

In **Type**, select **IVR**.

</Step>
<Step title="Add the metadata">

In **Meta Data**, enter the metadata you want to share with the provider when this call is triggered, as JSON. Metadata values are used to create dynamic text and convert it to speech. Placeholders must be inside double quotes, in the format `"{{ }}"`. For example:

```json
{
  "name": "{{name}}",
  "greet1": "Thank you for being with us."
}
```

Click **View Docs** in the editor for more details.

</Step>
<Step title="Override the IVR/Flow/Bot ID (optional)">

Expand **Additional Configuration** and select **Override IVR/Flow/Bot ID** to use a different IVR, flow or bot ID than the one configured in your integration.

</Step>
</Steps>

</Tab>
<Tab title="Call Connect">

### Call Connect

Call Connect, also known as a call bridge, connects two numbers. The first leg of the call is your bridge number, and the second leg is the recipient. No IVR or call flow is needed.

![](/images/voicecreate-v2-call-connect.png)

<Steps>
<Step title="Select Call Connect">

In **Type**, select **Call Connect**.

</Step>
<Step title="Enter the From Phone Number">

Enter the number used for the first leg of the call, usually a business, agent or customer care number. Use a static value, or a placeholder such as `{{from}}` to pick it from the payload.

</Step>
</Steps>

<Info>
The second leg (To) of the call is picked up from the `to` payload values when you fire a notification event. This number is visible and searchable on the Sent Logs page.
</Info>

Example request payload:

```json title="Voice Payload"
{
  "event": "<EVENT_NAME>",
  "to": {
    "voice": "<customer phone number>"
  },
  "data": {
    "from": "<business, agent or customer care number>"
  }
}
```

</Tab>
<Tab title="Text to Speech">

### Text to Speech

![](/images/voicecreate-v2-text-to-speech.png)

<Steps>
<Step title="Select Text to Speech">

In **Type**, select **Text to Speech**.

</Step>
<Step title="Enter the text">

In **Text to Speech**, type the content you want read out. It is spoken when the call connects to the recipient. You can add placeholders.

</Step>
</Steps>

<Note>
For Exotel, Text to Speech works through an IVR flow. The editor shows the URL to use, in the format `https://api.fyno.io/v1/<WORKSPACE_ID>/dynamic/text?textkey=text2speech`. See [Exotel setup](#provider-specific-setup).
</Note>

</Tab>
</Tabs>

## Provider-specific setup

Each provider processes voice data differently. Configure your provider as shown below.

<Tabs>
<Tab title="Kaleyra">

<AccordionGroup>
<Accordion title="IVR">

Metadata values are used in text-to-speech widgets to create dynamic text and convert it to speech. In Kaleyra Voice, use `{script:outbound:metadata-key-name}` to access a metadata value.

For example, to configure a menu with 2 options and 3 placeholders, `script:outbound:name`, `script:outbound:greet1` and `script:outbound:greet2`, set it up in Kaleyra as shown below.

![](/images/a015545-kaleyra_voice.png)

In Fyno, add the matching metadata as shown below.

![](/images/voice_template_ivr.png)

</Accordion>
<Accordion title="Call Connect">

No IVR or call flow is needed. Configure the **From Phone Number** in Fyno and pass the recipient in the `to` object of the payload. See [Call Connect](#call-connect).

</Accordion>
<Accordion title="Text to Speech">

Fyno prepares the dynamic content and passes it to Kaleyra using OBD (outbound dialing) calls. Type the content you want read out, and it is played on the OBD call. The content plays with a delay of 5 to 10 seconds, depending on its length.

</Accordion>
</AccordionGroup>

</Tab>
<Tab title="Exotel">

<AccordionGroup>
<Accordion title="IVR">

In Exotel, metadata values are used in text-to-speech widgets to create dynamic text. Configure the endpoint shown in the Fyno voice template to access the dynamic text for the call.

For example, if the metadata is `{ "Text2Play": "Dear Username, This is sample text to speech with dynamic content" }`, use this URL in the IVR text-to-speech greeting widget:

`https://api.fyno.io/v1/<WORKSPACE_ID>/dynamic/text?textkey=Text2Play`

To capture keypresses, use the **Passthru** widget in the Exotel platform while configuring the Fyno callback. Add the callback URL in each one to capture DTMF for every assigned keypress.

</Accordion>
<Accordion title="Call Connect">

No IVR or call flow is needed. Configure the **From Phone Number** in Fyno and pass the recipient in the `to` object of the payload. See [Call Connect](#call-connect).

</Accordion>
<Accordion title="Text to Speech">

Text to Speech is currently supported through IVR calls. Fyno prepares the dynamic content and makes it available at an endpoint.

To play the text over a call, create an IVR flow in Exotel. In the **Greetings** widget, configure this endpoint, which returns the dynamic text to play for the call:

`https://api.fyno.io/v1/<WORKSPACE_ID>/dynamic/text?textkey=text2speech`

</Accordion>
</AccordionGroup>

</Tab>
</Tabs>

## How to test a voice template

Use this feature to test a template thoroughly before including it in any Notification Event. This ensures early detection and resolution of any potential issues, for a seamless user experience.

<Steps>
<Step>

Click **Run Test** at the top right of the template. The test pop-up opens.

![](/images/template_voice_test_updated.png)

</Step>
<Step>

Enter either the mobile number of the recipient, or a `distinct_id`. **Make sure to enter the distinct_id of a Test User profile.**

</Step>
<Step>

Select a voice integration that is already configured in Fyno.

</Step>
<Step>

Click **Test** to place the call to the recipient with the selected integration. You see the success or failure message along with a link to the Sent Logs.

</Step>
</Steps>

## Save and go live

Click **Save** to save the template as a **Test** version. You can save different versions of the template this way. Use **Go Live** when you are ready to move your template to the **Live** version.

<Note>
If your workspace has a maker-checker workflow enabled for template management, **Go Live** needs an additional approval step. Choose from your designated approvers, who review and authorize the template changes. See [Approval flow](./approval-flow) for the steps.
</Note>
