When your template is ready, use the buttons at the top right of the template page. **Save as Draft** keeps it in Fyno, and **Send to Provider** submits it to Meta for review.

![](/images/waext-v2-save-send-buttons.png)

| | Save as Draft | Send to Provider |
| --- | --- | --- |
| **Where it goes** | Stays in your Fyno workspace. Nothing is sent to Meta. | Submitted to Meta for policy review. |
| **Can you edit it?** | Yes, at any time. | No, not while it's under review. |
| **Can you use it in notifications?** | No. | Yes, once Meta approves it. |
| **Use it when** | The content, variables or links aren't final, you're waiting for internal sign-off, or you're still preparing other languages. | The template is complete and ready for Meta's review. |

## Save as Draft

Click **Save as Draft** to save the template in your workspace without sending it to Meta. You can keep editing it and add languages later. Drafts don't appear when you create a Fyno WhatsApp template, and can't be used in notifications until they're approved.

## Send for approval

<Steps>
<Step title="Click Send to Provider">

The **Send For Approval** pop-up opens.

</Step>
<Step title="Select the languages">

Select the languages to submit. Each language is reviewed by Meta separately.

![](/images/waext-v2-send-for-approval.png)

- You can only submit languages whose content is valid. Valid languages show **Changes are valid**.
- Languages you don't select are saved as drafts, so you can keep editing them and submit them later.

</Step>
<Step title="Submit">

Click **Submit**. Meta reviews the template, which can take up to 24 hours. When the review is complete, the status is updated in Fyno under the **Synced** tab.

- **Approved:** The template is ready to use. Associate it with a Fyno WhatsApp template to use it in Notification Events.
- **Rejected:** Review the reason, edit the template and submit it again.

</Step>
</Steps>

<Note>
If template approvals are enabled in your workspace, **Send to Provider** needs an additional approval step. Choose from your designated approvers, who review the template before it's sent to Meta. See [Create an Approval Request](./create-approval-request) for the steps.
</Note>

## Template statuses

| Status | What it means |
| --- | --- |
| **Pending** | Submitted and waiting for Meta's review, which can take up to 24 hours. The template is read-only and can't be used to send messages. |
| **Approved** | Approved by Meta and ready to send messages. |
| **Rejected** | Rejected during review. You can edit it and submit it again. |
| **Paused** | Paused by Meta because of repeated negative user feedback, such as blocks or spam reports. It can't be used to send messages. |
| **Suspended** | Blocked because of policy or quality concerns. You can appeal the decision through Meta. |
| **Disabled** | Disabled by Meta because of repeated negative feedback or policy violations. It can't be used to send messages. |

For more detail, see Meta's <a href="https://developers.facebook.com/documentation/business-messaging/whatsapp/webhooks/reference/message_template_status_update" target="_blank" rel="noopener noreferrer">message_template_status_update webhook reference</a>.

## Draft and Synced tabs

Every template has two tabs on the left of the template page:

- **Draft:** The working copy you edit in Fyno. It isn't live until it's submitted and approved.
- **Synced:** The version and status from Meta. This is the live message customers receive, and it can't be edited here.

![](/images/waext-v2-draft-synced-tabs.png)

## Update an approved template

<Warning title="Meta reviews every update">
Meta treats an update as a new review request, and updates take longer to approve. Notifications that use the template may fail if there's live traffic during the review. We recommend creating a new template instead.
</Warning>

When you open an approved template that has no draft, Fyno asks how you want to make changes.

![](/images/waext-v2-edit-or-clone.png)

<Tabs>
<Tab title="Clone and exit (recommended)">

Creates a copy of the template so the original keeps working without interruption.

1. Click **Clone and exit**. The **Clone Template** pop-up opens, showing the current integration and WABA / namespace.
2. Enter a **New Template Name**, and in **Destination**, select the integration (WABA / namespace) to create the copy in.
3. Select **Clone all languages** to copy every language of the template, or clear it to copy only the current language.
4. Click **Clone Template**. The copy is saved as a draft. Edit it and send it for approval.

![](/images/waext-v2-clone-dialog.png)

**Use it when** the template is used in active campaigns, you can't afford any message disruption, or you're making major changes to content, variables or buttons.

For example, to change _"Get 10% off this weekend"_ to _"Get 20% off this weekend + free shipping"_, clone the template.

</Tab>
<Tab title="Edit here">

Opens a new draft version of the same template. The approved version keeps working until you send your changes for approval.

**Use it when** you're fixing small issues and the template isn't used in active campaigns. For example:

- Fixing a typo: `Hi {{1}}, your order is shipped` to `Hi {{1}}, your order is shipped.`
- Changing wording slightly: `Your package arrives today` to `Your package will arrive today.`
- Updating a support email address.

<Note>
If the template is in live traffic, message delivery may fail or be paused while Meta reviews the update.
</Note>

</Tab>
</Tabs>

### How draft versions work

A draft is an editable working copy that isn't approved yet. Changes to a draft don't affect live traffic. A draft is created when you:

- Create a new template.
- Click **Edit here** on an approved template.
- Add a new language to an existing template.
- Fix a rejected template.
- Clone a template.

When you save a draft of an approved template, a draft icon appears next to the template status, alongside the synced version.

### After the update is approved

Refresh the template in the **Fyno WhatsApp Template** that uses it. Until you do, active flows may keep using the previously approved version, which can affect live traffic and message delivery.
