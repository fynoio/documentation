Think of a **Fyno Template** as a master blueprint for your messages. Instead of writing text directly into your code, you design your messages inside Fyno. This means you can change your wording, fix typos, or update branding anytime you want **without** needing a developer to change code or redeploy the app.

## Where it fits in your workflow

A template sits in the middle of your core notification setup:

1. **Connect your provider:** Link your communication channels (for example, Twilio, SendGrid, or Gupshup).
2. **Design your template:** Create and personalize your message layouts *(this step)*.
3. **Trigger it:** Launch and orchestrate delivery using a workflow event.

<Tip>
By decoupling message content from application logic, you can safely experiment, update multi-channel copy, and test variations in real time without affecting active production features.
</Tip>

## Copying templates

You can copy **Fyno Templates** from one workspace to another, making it easy to reuse notification templates across multiple workspaces. The copy process is available only in workspaces where you have the **Owner** role.

<Warning>
Only **Fyno Templates** can be copied using this process. **External Templates** are not supported.
</Warning>

### Before you begin

Before copying templates, make sure the destination workspace is ready:

- Create any required integrations in the destination workspace.
- If the template uses reusable components, copy those components to the destination workspace before copying the template.

<Note>
Only the template and its associated template data are copied. Dependencies such as integrations and reusable components must already exist in the destination workspace.
</Note>

### Steps to copy templates

1. Switch to the workspace that contains the template you want to copy.
2. Navigate to **Templates → Fyno**.

    ![](/images/fyno-templates-list.png)

3. Locate the template you want to copy.
4. Click the **Three Dots (⋮)** menu on the template.
5. Select **Copy to another workspace**.
6. A checkbox appears beside every template in the list. Select one or more templates to copy.
7. Click **Copy Selected Templates**.
8. Choose which version to copy:
    - **Single template:** If the template has a Live version, choose whether to copy the latest **Live** or **Test** version. If the template only has a Test version, that version is copied.
    - **Multiple templates:** The latest **Live** version is copied where available. Otherwise, the latest **Test** version is copied.
9. In the **Destination Workspace(s)** dropdown, select up to five workspaces where you have the **Owner** role.
10. Click **Confirm** to begin the copy process.

Once the process completes, the selected templates are available in each destination workspace.

### How template versioning works

Suppose you copy a template from Workspace A to Workspace B. There are two versioning scenarios to keep in mind:

1. **The template does not exist in Workspace B:** The copy process always creates version v1 (Test).
2. **The template already exists in Workspace B:** The copy process creates a new standalone version that is neither Test nor Live.

For example, if the existing version in Workspace B is v1 (Test), the copy process creates a new version called v2. Select this version from the version dropdown beside the template name, then click **Save** to make it v2 (Test), or click **Go Live** to promote it to v2 (Live).

<Note>
This ensures that existing versions in the destination workspace are not overwritten, and gives you control over when to save or promote the copied template.
</Note>
