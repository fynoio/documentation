Handlebars is a JavaScript library used for creating dynamic templates.

It allows you to define templates with placeholders, and these placeholders are replaced with data when the template is triggered with the information sent in the payload.

Handlebars within Fyno support features like conditional operations, loops, date time formatting, partial searches, and custom helpers, making it a very cool tool to use when creating your templates.

## Generate Handlebars with Fyno AI

Don't want to write the syntax yourself? Describe what you need in plain language, and Fyno AI will generate a ready-to-use handlebar for you.

### Where to find it

You can open the generator from two places:

- **Variables panel:** Expand **Handlebars** > **Build your Own** and click **Generate**. If you'd rather build the logic yourself, this section also links to the Handlebar Builder.
- **AI menu on input fields:** Any field that supports handlebars has an AI menu. Choose **Generate Handlebar** from it.

The AI menu also has **Improve Handlebars**, which refines a handlebar that's already in the field instead of starting from scratch.

{/* Screenshot: Variables panel with Build your Own expanded */}

### Generate a handlebar

<Steps>
<Step title="Describe your requirement">
In the **Tell us your requirement** field, describe what the handlebar should do. For example: _Show the order date in short Indian format_. Then click **Generate**.
</Step>
<Step title="Let Fyno AI work">
Fyno AI reads your requirement, looks up the best-fitting helper from the handlebars library, and writes the handlebar, checking its syntax along the way. You can click **Cancel** at any point.
</Step>
<Step title="Review and copy">
Fyno AI shows the generated handlebar with a sample output, so you can confirm it does what you expect. For example:

```hbs title="Generated handlebar" wordWrap
{{formatDate order_date 'short' 'en-in'}}
```

```text title="Sample output" wordWrap
25/10/2023
```

Click **Copy** and paste it into your template.
</Step>
</Steps>

<Note>Always test a generated handlebar with a sample payload before publishing your template, just as you would with one you wrote yourself.</Note>

<Warning title='Check the quotes in generated handlebars'>
Arguments inside a handlebar must use single quotes, because double quotes can break your template, especially in emails. If a generated handlebar contains double quotes, replace them with single quotes before you use it.
</Warning>

### Write a better requirement

The more specific your requirement, the better the handlebar. Keep these in mind:

- **Name the exact variable.** Use the key path from your payload, such as `members.0.city` or `period.start`, instead of "the city" or "the date".
- **Describe the output you want.** Mention the format, locale, or timezone, such as DD/MM/YYYY, Indian number format, or IST.
- **Say what to show when a value is missing.** If a key can be empty or absent, tell Fyno AI what to fall back to.
- **Ask for one thing at a time.** If you need several pieces of logic, generate them separately and combine them in your template.

The examples below use the sample payload from [Handlebars in Fyno's Templates](#handlebars-in-fynos-templates).

### Not quite right? Regenerate with feedback

Click **Try Again** to open **Re-Generate Handlebar**. Refine your requirement and, optionally, choose what went wrong from the **Feedback** dropdown. Your feedback helps us improve Fyno AI.

| Feedback option | Choose this when |
|---|---|
| Doesn't work / throws an error | The handlebar fails when the template renders |
| Wrong output format | The output isn't formatted the way you asked |
| Wrong variable used | It references the wrong variable from your payload |
| Misunderstood my request | It solves a different problem from the one you described |
| Breaks on empty or missing values | It fails when a value is absent or null |
| Generation request failed | The request didn't complete |
| Other | None of the above |

Click **Generate** to try again, or **Back** to return to the previous result.

### If generation fails

If Fyno AI can't generate a handlebar, you'll see **Oops! That didn't go as planned**. Click **Try Again**, ideally with a more specific prompt. If an earlier attempt had succeeded, you can also click **View previous Handlebar** to go back to that result.

## Handlebars in Fyno's Templates

To understand how handlebars work, we first need to establish a sample payload, based off which the Handlebars function and applicability can be demonstrated.

```json Sample Payload
{
  "members": [
    {
      "first_name": "Ashwin",
      "last_name": "Agarwal",
      "city": ""
    }
  ],
  "investments": [
    {
      "amount": 10,
      "company": "L&T"
    },
    {
      "amount": 20
    }
  ],
  "companies": {
    "L&T": "India",
    "Apple": "USA"
  },
  "user_type": "pro",
  "period": {
    "start": "2023-10-01",
    "end": "2023-10-03"
  },
  "classification": ["active", "pro"]
}
```

Fyno has default as well as custom **handlebars** that you can use in your templates. Let's have a look at what these are and how to use them using the above payload and data as example responses.

<Warning title='🚧 Double Quotes within Handlebars {{" "}} may break your templates!'>
<p>Double quote may break your syntax in HBS, especially in emails! And nobody wants that!</p><p>**For example:** Use `{{math number1 '+' number2}}` instead of `{{math number1 "+" number2}}`.</p><p>Use single quotes `{{' '}}` instead! :sunglasses:</p>
</Warning>

<Accordion title="To check if multiple variables equal a certain value (AND and OR options)">

```hbs title="Format" wordWrap
{{#if (and/or (eq/ne/lt/gt/lte/gte variable 'value') (eq/ne/lt/gt/lte/gte variable 'value'))}}
  Content Here
{{else}}
  Content Here
{{/if}}
```

```hbs title="Example" wordWrap
{{#if (or (eq investments.0.company 'L&T') (eq investments.0.company 'Apple'))}}
  First investment is either L&T OR Apple
{{/if}}

{{#if (and (eq investments.0.company 'L&T') (gt investments.0.amount 5))}}
  First investment is L&T and investment amount is greater than 5
{{/if}}

{{#if (and (ne user_type 'pro') (gte investments.0.amount 10))}}
  User is not pro but first investment is greater than or equal to 10
{{else if (and (eq user_type 'pro') (lt investments.0.amount 10))}}
  User type is pro but first investment is less than 10
{{else if (and (eq user_type 'pro') (eq investments.0.amount 10))}}
  User type is pro and first investment is equal to 10
{{/if}}
```

```text title="Output" wordWrap
First investment is either L&T OR Apple

First investment is L&T and investment amount is greater than 5

User type is pro and first investment is equal to 10
```

</Accordion>
