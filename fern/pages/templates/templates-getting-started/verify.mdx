Fyno Verify is a fully managed API for multichannel user verification by OTP or link. A single API handles OTP generation, delivery and verification securely, so you can improve your onboarding and login flows.

Verifying that a new user is who they say they are is an essential first step in your relationship with them. It reduces spam and fraud on your site and keeps your users secure.

<Info>
Fyno Verify supports SMS, Email, WhatsApp, Push, InApp and Voice.
</Info>

## Configure Fyno Verify

<Steps>
<Step title="Open Fyno Verify">

In the template editor, go to **System Variables → Verify** in the left panel and click **Configure**.

![](/images/dyncontent-v2-verify-panel.png)

</Step>
<Step title="Turn on OTP, Link or both">

In the **Fyno Verify** pop-up, turn on **OTP**, **Link** or both, then configure each one. See [OTP settings](#otp-settings) and [Link settings](#link-settings).

![](/images/dyncontent-v2-verify-modal.png)

</Step>
<Step title="Save">

Click **Done**.

</Step>
</Steps>

<Tip>
You can configure both OTP and Link in the same template.
</Tip>

## OTP settings

![](/images/dyncontent-v2-verify-otp.png)

| Setting | What it does |
| --- | --- |
| **Type of OTP** | Choose **Numeric** or **Alphanumeric**. |
| **No. of characters** | The OTP length, from 3 to 6 characters. |
| **Validation time limit** | How long the OTP is valid, between 60 seconds and 48 hours. |
| **No. of attempts** | The number of allowed retries, from 1 to 10. |
| **Use destination as id** | Select **Yes** to send the destination (email address, phone number and so on) as the ID when you verify the OTP the user entered. Select **No** to send the `request_id` in the Fyno Verify API request instead. |
| **Channel Specific** (optional) | By default, the same OTP is sent to every channel in the template. Select **Different OTP for all channels** to send a different OTP to each channel. |

<Note>
Use `{{$fyno.$otp}}` as the OTP placeholder in your template.
</Note>

## Link settings

![](/images/dyncontent-v2-verify-link.png)

| Setting | What it does |
| --- | --- |
| **Validation time limit** | How long the link is valid, between 60 seconds and 48 hours. |
| **Channel Specific** (optional) | By default, the same link is sent to every channel in the template. Select **Different links for all channels** to send a different link to each channel. |
| **Redirect To** (optional) | The URL users are redirected to when they click the verification link. If you leave it empty, users see a success screen once the link is verified. |

<Note>
Use `{{$fyno.$link}}` as the link placeholder in your template. The generated URL follows the format `https://fy1.in/verify/x`, where `x` is a 32-character string.
</Note>

## Verify the OTP with the API

Call the Fyno Verify API to validate the OTP the user entered. The request depends on the **Use destination as id** setting. `WSID` is your Workspace ID.

<Tabs>
<Tab title="Use destination as id: No">

Send the `request_id` and the OTP:

```text wordWrap
https://api.fyno.io/v1/{{WSID}}/live/verify/validate?request_id=0b59df61-c587-4f44-a669-f0177a161b81&otp=2811
```

</Tab>
<Tab title="Use destination as id: Yes">

Send the OTP and the destination:

```text wordWrap
https://api.fyno.io/v1/{{WSID}}/live/verify/validate?otp=2811&destination=91xxxxxxxxxx
```

</Tab>
</Tabs>

### How verification is logged

For example, a bank sends a login OTP by both SMS and email. How Fyno updates the Sent Logs depends on the **Channel Specific** setting:

| Scenario | Same OTP for all channels | Different OTP for all channels |
| --- | --- | --- |
| **What the user receives** | The same OTP in SMS and email. The user can enter it from either channel. | A different OTP in each channel, for example `4561` in SMS and `7891` in email. |
| **Validation succeeds** | Marked **Verified** for both SMS and email. | Marked **Verified** only for the channel whose OTP was entered. For example, entering `4561` marks SMS as **Verified**. |
| **Validation fails** | Marked **Failed to Verify** for both SMS and email. | Marked **Failed to Verify** for both SMS and email. |

## How Fyno Verify works

For example, brand ABC uses Fyno Verify to authenticate its users.

![](/images/fyno_verify_flowchart.png)

<Steps>
<Step>

The user enters their phone number or email address in ABC's app or website.

</Step>
<Step>

ABC triggers a Fyno notification event from its backend, which generates an OTP.

</Step>
<Step>

Fyno sends the OTP to the user through the channels configured in the notification event.

</Step>
<Step>

The user enters the OTP in ABC's app or website.

</Step>
<Step>

ABC's backend calls the Fyno Verify API to validate the OTP. See [Verify the OTP with the API](#verify-the-otp-with-the-api).

</Step>
<Step>

Fyno verifies the OTP and returns one of these responses to ABC's application:

<Tabs>
<Tab title="Verified">

```json title="200"
{
  "status": "ok",
  "_message": "verified"
}
```

</Tab>
<Tab title="Attempt failed">

```json title="400"
{
  "status": "error",
  "_message": "verify-attempt-failed",
  "attempt_left": 2
}
```

</Tab>
<Tab title="Attempts exceeded">

```json title="400"
{
  "status": "error",
  "_message": "verify-attempt-exceeded",
  "attempt_left": 0
}
```

</Tab>
<Tab title="Invalid request">

```json title="400"
{
  "status": "error",
  "_message": "Not a valid request"
}
```

</Tab>
</Tabs>

</Step>
<Step>

If validation fails, the user can retry, up to the number of attempts you configured. Once the user has used all their retries, ABC decides how long to wait before letting the same user try again.

</Step>
</Steps>
