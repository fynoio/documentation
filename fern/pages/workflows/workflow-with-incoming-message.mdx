This functionality is ideal for creating automated WhatsApp conversations using predefined templates and notification event triggers. It's also useful for capturing and updating customer SMS responses in your system.

You can also capture Keypress values during a Voice call and trigger a workflow.

## Example: COD order confirmation

For example, you can configure the below flow using our Workflow:

<Steps>
  <Step>Send a WhatsApp to customers who placed a COD order to either confirm or cancel their order.</Step>
  <Step>Based on customer's response, update the status in your system by calling your API.</Step>
  <Step>Send order status update confirmation to the customer.</Step>
  <Step>Ask customer if they want to update their phone no.</Step>
  <Step>If yes, let them enter a phone no and call an API to update it in your system. If user selects No, the flow will end.</Step>
</Steps>

The animation below follows two customers through this flow, plus what happens if your API call fails.

## Step 1: Create a WhatsApp template to initiate a conversation

![](/images/virtual-num-template-preview.png)

<Steps>
  <Step title="Create the template">
    Create a Fyno Template with the content and Quick Reply options as shown.

    ![](/images/virtual-num-edit-template.png)
  </Step>
  <Step title="Add the Quick Reply options">
    In the template, you can see 2 Quick Reply options, **Confirm** and **Cancel**. When the user clicks any Quick Reply option, it will trigger a workflow.
  </Step>
  <Step title="Pass extra data in the button (optional)">
    If you want to pass additional information when the user clicks a Quick Reply button, add a JSON payload in the **Custom Id** section.

    For example, to pass `order_id` and the template name to the Workflow, add a JSON payload as shown below. You can add any payload up to 126 characters.

    ```json
    {"order_id": "ORD-10245", "template": "order_confirmation"}
    ```

    ![](/images/183f9ed-dynamic_payload_QR.png)
  </Step>
</Steps>

## Step 2: Design a Workflow to decide what WhatsApp message to send based on user response

![](/images/virtual-num-workflow.png)

Here is the trigger setup at a glance.

![](/images/virtual-number-setup.gif)

### Set up the Virtual Number trigger

<Steps>
  <Step title="Select the trigger">
    Create a workflow and select **VIRTUAL NO.** from the triggers. The **Mobile No.** panel opens. To pick a different trigger, click **CHANGE TRIGGER**.
  </Step>
  <Step title="Select your WhatsApp Business number">
    Under **Mobile Number**, select the number to which users send their response. You can add more than 1 WhatsApp Business number, so any replies received on any of these numbers will trigger this workflow.

    ![](/images/virtual-number-trigger.png)

    <Note>
    Don't see your number? Click **GO TO INTEGRATIONS** to set up a new incoming number for WhatsApp, or contact [support@fyno.io](mailto:support@fyno.io).
    </Note>
  </Step>
  <Step title="Store the button payload data (optional)">
    You can store the data you are passing in the button payload if you want to use that data further in the workflow. In this example, we are passing `order_id` and the template name in the button payload.

    Expand **Store Button Payload Data (optional)**, enter a name in **Stored variable**, and pick where the value comes from in **Variable value from payload**. Click **ADD ANOTHER** to store more values.

    ![](/images/virtual-number-store-payload.png)
  </Step>
  <Step title="Simplify the payload (optional)">
    Incoming message payloads have long keys. Click **SIMPLIFY PAYLOAD** to open the **Payload Mapper**, where you can give a key a short name to use across the workflow.

    Enter a name under **MAPPER VARIABLES**, then pick a payload key or enter HBS under **PAYLOAD/HBS**. Click **ADD** for more, then **CONFIRM**.

    ![](/images/virtual-number-payload-mapper.png)
  </Step>
</Steps>

### Check what the user replied

<Steps>
  <Step title="Add a condition for the reply">
    Add a condition to check what the user has sent to your WhatsApp Business number. In this use case, the user could have sent either 'Confirm' or 'Cancel'. The variable `simplified.message.button.text` will contain the Quick Reply text your customer has sent. In this case, we have assumed the user has sent 'Confirm'.

    ![](/images/incoming_workflow_condition.png)
  </Step>
  <Step title="Check the template name (optional)">
    If you want to make sure this response comes from the exact template message you sent to the user, add one more condition to check the template name as shown.

    Add the condition as Custom Value `$input.body.entry.0.changes.0.value.messages.0.button.payload.template` equals `order_confirmation`. This accesses the template variable we added in the WhatsApp template (see step 3 in Step 1).

    ![](/images/incoming_workflow_multiple_condition.png)
  </Step>
  <Step title="Repeat for Cancel">
    Repeat the steps above for the 'Cancel' flow.
  </Step>
</Steps>

### Update the order in your system

<Steps>
  <Step title="Call your API">
    Add the **API** action block to the workflow canvas to send the user response to your system and update the order status when the user clicks either 'Confirm' or 'Cancel'.

    You need to post a request to your webhook. Make sure you have allow-listed your URL. Read more about it [here](./allowlist-url).

    ![](/images/incoming_workflow_call_api.png)
  </Step>
  <Step title="Check the update worked">
    Add a condition to check if the HTTP response code is `200`, as shown below.

    ![](/images/incoming_api_status_check.png)
  </Step>
</Steps>

### Notify the user and wait for their reply

<Steps>
  <Step title="Send the order status">
    If the HTTP status code is `200`, send a notification to the user confirming the status of the order.

    - Map the mobile no in the destination section. You can choose `simplified.source` from the dropdown.
    - Map all the placeholders used in the template in the data section, in the format `{{$http_response.data.<variable>}}`.

    ![](/images/incoming_order_status_notification.png)
  </Step>
  <Step title="Wait for the user's reply">
    Add a **Wait For Reply** node to store the user response and use it further in the flow. You can also set how long to wait for the reply. In this example, we wait for 30 minutes and save whether the user wants to change their phone no.

    ![](/images/incoming_workflow_wait_for_reply.png)
  </Step>
  <Step title="Act on the reply">
    Using this, you can decide whether to call an API to update the phone no (if the user clicked Yes) or end the flow.

    ![](/images/incoming_workflow_final.png)
  </Step>
</Steps>

<Note>
To send simple and interactive WhatsApp messages, you can directly use the **Send Message** node with a WhatsApp template. No need to create a notification event in such cases.
</Note>

### Nodes you can use

These nodes are available after a Virtual Number trigger:

![](/images/virtual-number-nodes.png)

| Node | What it does |
|------|--------------|
| **Notification Event** | Sends a notification using one of your notification events. |
| **API** | Calls an allowlisted API, for example to update your system. |
| **Subscription** | Updates the user's notification subscription. |
| **User Profiles** | Stores or updates details about the user. |
| **Send Message** | Sends a WhatsApp message directly from a template, without a notification event. |
| **Write to Spreadsheet** | Writes data from the workflow to a spreadsheet. |
| **Subflow** | Bundles repeated nodes so you can reuse them across the workflow. |
| **AI Magic Match** | Sends the user down a branch based on the meaning of their reply. |
| **Condition** | Sends the user down a branch based on a variable and a value. |
| **Wait For Reply** | Waits a set time for the user's reply and stores it. |

## How to test an Incoming message workflow?

While configuring the trigger, expand **Test Numbers (optional)** and add up to 3 mobile numbers, with country codes. All messages sent from these numbers will trigger the _latest Test version of the Workflow_.

![](/images/virtual-number-test-numbers.png)

## Request Approval to Go Live

If your workspace has **Approval** turned on, clicking **GO LIVE** creates an approval request instead of publishing the workflow right away.

![](/images/workflow-request-approval.gif)

<Steps>
  <Step>Click **GO LIVE** to open the **Request Approval** window.</Step>
  <Step>Select one or more approvers from **Select Approvers**.</Step>
  <Step>Add a note in **Write a Message**. Select **Go live on approval** to publish automatically once approved.</Step>
  <Step>Click **REQUEST**.</Step>
</Steps>

You can read more about it on the [Approval Request](/approval-request) page.
