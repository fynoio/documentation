A Mixpanel trigger starts your workflow whenever Mixpanel syncs a cohort to Fyno. You can send different notifications to users when the cohort is first synced, when users join it, and when they leave it.

## Prerequisites

1. Ensure relevant notification events which will be configured as part of Workflow are created.
2. Ensure at least 1 allowlist API is configured if you want to receive delivery reports.

## Example: EMI reminders from a cohort

Say you have a Mixpanel cohort called `emi-due` for users whose EMI is due this week. Every Mixpanel cohort can be linked to one of 3 actions, and each one becomes its own branch on the **Cohort** node.

![](/images/mixpanel-example.gif)

| Action | Who it includes | In this example |
|--------|-----------------|-----------------|
| **First Run** | All the users during the initial cohort sync. Use this option if you want to do a one time sync. | Send `emi-reminder` to everyone in the cohort. |
| **Added** | Users who joined the cohort since the last sync. | Send `emi-reminder` to the new member. |
| **Removed** | Users who left the cohort since the last sync. | Send a payment thank-you to users who have paid. |

## How to configure a Trigger using Mixpanel cohort

Here is the setup at a glance.

![](/images/mixpanel-setup.gif)

<Steps>
  <Step title="Create the workflow">
    Navigate to **Workflows** from the left navigation panel. If you have already created a few workflows, you can see them in card view.

    Click **CREATE**, enter a name and click **SUBMIT**. The workflow canvas opens with the list of triggers.
  </Step>
  <Step title="Select the Mixpanel trigger">
    Select **MIXPANEL** from the triggers. The **Mixpanel** panel opens on the right. To pick a different trigger, click **CHANGE TRIGGER**.
  </Step>
  <Step title="Add Custom Fields (optional)">
    By default, `mixpanel_distinct_id` and `mixpanel_cohort_name` are sent for every Mixpanel cohort. If your cohort has additional fields, enter each field name in **Mixpanel Custom Fields** and press ENTER.

    <Note>
    Make sure the case matches the field name in Mixpanel.
    </Note>

    In this example, `plan_type` is added as a custom field.

    ![](/images/mixpanel-trigger.png)
  </Step>
  <Step title="Add a Cohort and enter its name">
    Add a **Cohort** node from the panel on the left and connect it to the trigger. Under **Cohort Name**, enter the cohort name. Make sure the name matches the cohort created in Mixpanel.

    The Cohort node shows 3 outputs, **First Run**, **Added** and **Removed**. Connect the next steps to the ones you need.

    ![](/images/mixpanel-cohort-name.png)
  </Step>
</Steps>

## Action

Once the trigger and cohort are set up, add nodes from the panel on the left of the canvas.

![](/images/mixpanel-nodes.png)

| Node | What it does |
|------|--------------|
| **Notification Event** | Sends a notification using one of your notification events. |
| **Cohort** | Links a Mixpanel cohort to the trigger, with **First Run**, **Added** and **Removed** outputs. |
| **Subflow** | Bundles repeated nodes so you can reuse them across the workflow. |
| **AI Magic Match** | Sends the user down a branch based on the meaning of their input. |
| **Condition** | Sends the user down a branch based on a variable and a value. |

The two you will use most are **Notification Event** and **Cohort**.

<Tabs>
  <Tab title="Notification Event">
    **Notification Event** refers to the notification events created within Fyno and can be called in response to an action in Mixpanel. Connect it to a **First Run**, **Added** or **Removed** output.

    <Steps>
      <Step title="Select the notification event">
        Under **Select Notification Event**, choose a relevant **Notification Event** from the dropdown, specific to this Mixpanel action.

        The **Map data** section uses the **Test** version of the notification event.
      </Step>
      <Step title="Map the destination">
        Under **DESTINATION**, specify which field from the Mixpanel cohort is the recipient.

        - **Distinct ID:** If you are using Fyno's user profile, select the value for Distinct ID, for example `{{mixpanel_distinct_id}}`, or a custom variable created using **Simplify**.
        - **Channel destination:** All the channels configured in the template linked to the selected notification event appear here. If you are not using Fyno's user profile, map the channel destination with a field from the Mixpanel cohort. In this example, the template linked to `emi-reminder` has only Email as the channel, which is why you see **Email**.

        ![](/images/mixpanel-notification-event.png)
      </Step>
      <Step title="Map the placeholders">
        Under **DATA**, you will see all the fields specified as **Placeholders** (dynamic values) in the template linked to the selected notification event. Map each one to a value from the cohort. If you do not see this section, there are no placeholders in the template.

        ![](/images/mixpanel-data.png)
      </Step>
      <Step title="Add Additional Data (optional)">
        Use **ADDITIONAL DATA** for placeholders used in a route or not saved in the template. For instance, if your template contains `Hi {{ name }}` but you did not add `name` as a placeholder during template creation, Fyno still identifies it as a placeholder since it uses the `{{ }}` syntax.

        Enter the key in **Placeholder name**, and select a value in **Placeholder value**. Click **ADD ANOTHER** to add more.

        ![](/images/mixpanel-additional-data.png)
      </Step>
    </Steps>
  </Tab>
  <Tab title="Cohort">
    You can add multiple cohorts to the Mixpanel trigger as shown below. This helps you add as many cohorts as you need to a single Workflow and handle all your use cases.

    ![](/images/d92e66f-mp_multiple_cohorts_updated.png)

    <Info>
    Cohorts can only be connected to the trigger. It is not possible to add cohorts after Notification Event nodes.
    </Info>
  </Tab>
</Tabs>

## Workflow URL

Once you save or go live with your workflow, copy the Workflow URL. We provide URLs for both **TEST** and **LIVE**. Copy both URLs and configure them in Mixpanel, as shown in the next section.

To get the Workflow URL, click the Workflow URL icon next to the **GO LIVE** button at the top. The URL is auto-generated when you create the workflow. For more on this window, see [Access and Settings](/workflows#access-and-settings) on the Workflows page.

![](/images/workflow-header-url-icon.png)

<Tabs>
  <Tab title="Public">
    By default, the access level of a workflow is public. Choose **LIVE** or **TEST** to see that URL, and click the copy icon to copy it.

    Below the URL, the window shows the **Username** and **Password** to use in the HTTP Basic Auth settings when you create the integration in Mixpanel. Click the copy icon next to each one.

    ![](/images/mixpanel-workflow-url-public.png)

    <Info>
    Workflows are public by default. If you turn on **Restricted** after the workflow is created and save it, you must use the Restricted URLs (Live and Test) when running the workflow.
    </Info>
  </Tab>
  <Tab title="Restricted">
    To use restricted access, turn on the **Restricted** toggle and click **SAVE CHANGES**. Restricted workflows can be run only with your Fyno API Key.

    The **Username** stays the same. For the **Password**, use your Fyno API Key in Mixpanel.

    ![](/images/mixpanel-workflow-url-restricted.png)

    <Tip>
    Keep the workflow public while you build and test it, then switch it to **Restricted** once it is ready.
    </Tip>
  </Tab>
</Tabs>

<Tip title='You can update the token using the "Customize Token" option in the workflow header.'>
Since the workflow URL can be called from anywhere, it is a good idea to update the token if you feel it has been compromised. Always remember to update the workflow URL (with the new token) in Mixpanel.
</Tip>

## Connect the Workflow URL in Mixpanel

To send cohort data from Mixpanel to your workflow, add the Workflow URL to Mixpanel.

<Steps>
  <Step title="Open Integrations">
    In Mixpanel, click the **Data Management** icon in the top navigation and go to **Integrations**.
  </Step>
  <Step title="Add a Custom webhook">
    Select **Custom webhook** and click **Add connection**.
  </Step>
  <Step title="Fill in the details">
    Enter a **Connector Name** to identify the connection. Paste the Workflow URL in **URL**, then enter the **Username** and **Password** from the Workflow URL window. For restricted workflows, the password is your Fyno API Key.
  </Step>
</Steps>

## Request Approval to Go Live

If your workspace has **Approval** turned on, clicking **GO LIVE** creates an approval request instead of publishing the workflow right away.

![](/images/workflow-request-approval.gif)

<Steps>
  <Step>Click **GO LIVE** to open the **Request Approval** window.</Step>
  <Step>Select one or more approvers from **Select Approvers**.</Step>
  <Step>Add a note in **Write a Message**. Select **Go live on approval** to publish automatically once approved.</Step>
  <Step>Click **REQUEST**.</Step>
</Steps>

You can read more about it on the [Approval Request](/approval-request) page.
