The **Wait for Reply** widget is used to pause workflow execution until a user response is received within a specified duration.

This widget is commonly used in conversational workflows such as WhatsApp journeys, feedback collection, approvals, and user interaction flows.

## Example

The workflow asks "Would you like to update your phone number?" and waits up to 1 day. When the first user taps **Yes**, the reply is saved in the stored variables and the workflow continues. When the second user doesn't reply, the timeout action sends a reminder after 1 day.

## Steps to configure Wait for Reply Widget

<Steps>
  <Step title="Add the widget">
    Drag and drop the **Wait for Reply** widget into the workflow and connect it to the required workflow step.
  </Step>
  <Step title="Set the wait duration">
    - **Time:** Numeric value for the waiting period, for example `1`.
    - **Unit:** Duration unit such as minutes, hours, or days, for example **days**.
  </Step>
  <Step title="Handle no reply (optional)">
    Turn on **Define action when reply is not received** if you want the workflow to handle timeout scenarios. This allows workflows to trigger alternate actions when the user does not respond within the configured duration.
  </Step>
  <Step title="Configure Stored Variables">
    Stored variables are used to save the response payload received from WhatsApp or other supported channels.

    | Field | Description |
    | --- | --- |
    | **Stored Variable** | Name of the custom variable where the response will be stored. |
    | **Payload** | Payload field selected from the mapper to store in the variable. |

    Use **Add Another (+)** to create multiple stored variable mappings. This is useful when multiple payload fields need to be saved separately.
  </Step>
  <Step title="Save">
    Save the workflow configuration.

    During workflow execution, the workflow waits for the configured reply duration and stores the received response payload in the mapped variables.
  </Step>
</Steps>

<Note>
If no reply is received within the configured duration, the workflow can proceed with the fallback or timeout action if configured.
</Note>
