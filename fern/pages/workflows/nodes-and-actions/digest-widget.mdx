Digest Notifications work by collecting multiple trigger events, aggregating them into a single message, and delivering it to the user. This becomes useful when a user needs to be notified of a large number of events and you want to avoid sending too many notifications.

## How Digest works

<CardGroup cols={3}>
  <Card title="One digest per window" icon="layer-group">
    Creates a digest for each specified time window.
  </Card>
  <Card title="Starts on the first event" icon="play">
    The window starts from the first event trigger.
  </Card>
  <Card title="Sends when the window ends" icon="paper-plane">
    The message is sent when the digest window ends.
  </Card>
</CardGroup>

**Best for:**

- Consistent communication intervals
- Periodic updates
- Non-urgent, informational notifications

This approach ensures regular updates without overwhelming users, regardless of activity levels or triggers.

## Example

| Part | Details |
|---|---|
| **Scenario** | A user has 5 SIPs scheduled on the 1st of every month, and all SIPs failed due to insufficient balance. |
| **Problem** | Sending a notification for every SIP failure could spam the user. |
| **Solution** | Use digest notifications: collect SIP failures over a set period (for example, 1 hour) and send one summary notification. |

![Digest collecting 5 SIP failures into one notification](/images/digest-example.gif)

## Steps to set up a Digest

This use case can be implemented with the below steps.

![](/images/Workflow_Digest_Config.png)

<Steps>
  <Step title="Create the workflow">
    Create a Workflow with **Webhook** as the trigger. You can read how to create it [here](./workflow-webhook-trigger-setup).
  </Step>
  <Step title="Add a Digest node">
    After you add a **Digest** node in the workflow editor, each node below it is triggered only once in the specified digest interval.

    <Tip>
    Nodes you add before the Digest node are still triggered in real time, so you can send some messages right away and digest the rest.
    </Tip>
  </Step>
  <Step title="Set the Digest Key">
    Provide a unique key to identify the user. This helps the workflow digest the notifications for that user. In this case, the user's `profile_id` in your system is the Digest Key.
  </Step>
  <Step title="Set the Time Period">
    Specify how long you want to digest the notifications, from a minimum of 1 second to a maximum of 7 days.
  </Step>
  <Step title="Sum digest data (optional)">
    Select this checkbox if you want to add up a value across all digested events. For example, use it to calculate the total SIP amount across all the SIPs that failed.

    - **Custom Variable:** The variable you will use in your template. For example, if you add `SIPAmount`, your digest variable will be `$digest.sum.SIPAmount`.
    - **Digest Key:** Select the key whose values you want to add up.
  </Step>
  <Step title="Add a Notification Event">
    Add a **Notification Event** after the Digest node, depending on the communication you want to send.
  </Step>
</Steps>

## How to use Digest data in a Template?

In the template editor, you will find the system variables on the left.

For example, to notify users with the list of failed SIPs, you can do it as shown:

![](/images/workflow_digest_example.png)

| Variable | What it gives you |
|---|---|
| `$digest.head` | The first 5 payloads, by default. You can see the payload in the Logs section. |
| `$digest.tail` | The last 5 payloads, by default. You can see the payload in the Logs section. |
| `$digest.count` | The total count of payloads received. |
| `$digest.sum.<variable>` | The total of the value set in **Sum digest data**, for example `$digest.sum.SIPAmount`. |

In this example, `$digest.head.SIP_name` gives you the SIPs which failed.

## How to see logs for Digest?

You can see the Digest logs in **Logs** > **Workflow**. Sample logs below.

![](/images/workflow_digest_logs.png)

| Section | What it shows |
|---|---|
| **Summary** | The Digest Key, and a count of the requests digested. Total time taken is updated once the Digest is completed. |
| **Head** | The first 5 payloads received for the Digest. |
| **Tail** | The last 5 payloads received for the Digest. |
