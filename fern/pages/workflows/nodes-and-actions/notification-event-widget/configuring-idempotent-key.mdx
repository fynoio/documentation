Workflows support idempotency, ensuring you can safely retry requests without the risk of performing the same operation twice. This feature proves invaluable in scenarios where an API call gets interrupted in transit, leaving you without a response.

For instance, if a request to send a notification doesn't go through due to a network glitch, simply retry the request using the same idempotency key. This guarantees that no more than one notification will be sent.

You can read more about it [here](./idempotent-requests).

## Example

The `order-confirmed` notification event uses `{{order_id}}` as its Idempotent Key for 24 hours. The first request is sent, but its response is lost. The retry has the same key, so it is not sent again. A new order has a different key, so it is sent normally.

## Steps to configure Idempotent Key

<Steps>
  <Step title="Open the notification event settings">
    After adding a notification event to the workflow, click the **Settings** icon in the top right corner.

    ![](/images/workflow_event_idempotent.png)
  </Step>
  <Step title="Fill in the Idempotent tab">
    Go to the **Idempotent** tab and add the below details.

    | Field | What to enter |
    |---|---|
    | **Idempotent Key** | A key that prevents this notification event from being fired multiple times to a user, for a set duration, when there is no change in the data. |
    | **Time** | How long you want to prevent duplicate notification events from sending. The duration should be between 1 second and 24 hours. |
    | **Units** | Seconds, Minutes, Hours or Days. |

    ![](/images/workflow_configure_idempotent_key.png)
  </Step>
</Steps>

<Note>
There is no length limit for the idempotency key, but we recommend using 256 characters or less. These keys are purged from the system after 24 hours.
</Note>
